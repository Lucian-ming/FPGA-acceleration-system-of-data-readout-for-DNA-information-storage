## 3. 不可让步的纪律

1. **唯一 Git 写入者是你。** 禁止 `git add -A` / `git add .`；
   **提交必须 `git commit -m "..." -- <显式路径>`**（索引是整棵工作树共享的，
   两个方向都出过事）。禁止 `Co-authored-by` 尾注。推完确认 `main...origin/main` 为 `0/0`。
2. **制品与源码同源是本项目的核心资产。** 改了 `sw/app/**` 或 `hw/ip/*/hdl/**`
   就必须重建、重烧、重跑 G3、更新 `hw/build/export/SHA256SUMS`，
   **源码与制品放进同一个提交**。`928e156` 分两次提交，中间那个 commit
   「源码新、制品旧」，而整文件 SHA 校验对此完全失明。
3. **报任何板端耗时都必须给重复次数与中位数。** 单次运行只能精确到 ±0.5 s——
   波动不是噪声是量化（lwIP 慢定时器，簇间恒 0.47~0.49 s，簇内仅 ±0.01 s）。
   两个配置差 0.4 s 完全可能只是落在不同格点上。
4. **同时只能有一个 TCP 连接连板子。** 固件用的是 lwIP 单例 `g_conn`；
   G3 跑的时候另开探针 = 直接 FAIL（我自己犯过）。
5. **推算不许写成实测。** 每条对外可说的话都要在 `docs/18-evidence-ledger.md` 里
   有「判据 / 证据路径 / 复现命令 / 边界」四件套；该文件还有一张「不能说的话」清单。
6. **失败也是产出。** 负结果要写进文档并保留留证，不许悄悄删。
   但**死代码不是证据**——清理的出口见 `AGENTS.md` 代码卫生 §5 的退休三条。
7. **`data/R0.83_data/`（D0 真实数据集）不进仓库**，用户已明确决策。
8. 派子 agent 时，必须在 prompt 里指定 `--agent <短名>` 并要求它按
   `CLAUDE.md` 的规则 `start` / `update` / `done`。名字不得与在跑的重复。

## 4. 踩过的坑（省下来的时间比读它花的多）

- `XAxiDma_BdRingGetFreeCnt()` 返回的是 **Free 组**的计数，**不是可用空间**。
  TX_STREAM 压缩失败四次，其中两次死在这个误解上，第四次用对了变量却产出逐字节
  相同的结果——说明原因根本不在那里。**已放弃，不要再试**（`docs/17` §3.0.6）。
- poll 的节拍**同时也是 BD 环的节流**。P0 修复 v1 把批量化做过头，
  `submitted=640 > ring free=512` 直接打挂 Stage1。`stage1_dna.c:178` 早就写着警告。
- `PKT_CONFIG_OK` **不代表接受**——固件用同一个包类型带非零 reason code 表示拒绝。
  我据此发布过一条错误的「板端不校验」结论并撤回，正确结果是 7/7 全对。
- 黄金向量里有 **FFT 浮点噪声**导致的同分并列，位置不唯一。
  判据要写成「得分相等 + 位置落在并列集合内」，不是「位置相等」。
- `.gitignore` 写 `data/` 会让 git 根本不下降进目录，`!data/MANIFEST.md` 永远失效；
  必须写 `data/*`。
- 移动文件之后**必须重跑 `tools/run_sim.sh`**：我移了 6 个 TB 把回归弄坏过。
- 五小时用量限额是真实约束：**长任务前先把结论落盘**，不要把大段推理留在上下文里。

## 5. 对外口径（`docs/17` §4，这条最容易翻车）

**能说**：可复现的端到端正确性、四级逐级取证、故障注入 20/20 恢复、
资源天花板的定量证伪、Amdahl 归因、诚实的 CPU 对照表。
**不能说**：任何形式的「比 CPU 快」、任何未实测的能效数字、
任何把仿真核心加速比（1.929x）当成端到端收益的表述。

**这个项目的竞争力不在加速比，在于它是少数几个敢把自己的性能天花板测出来、
证伪掉自己三个方向、并把每条结论的边界写清楚的参赛作品。**
守住这一点，比多挤出 10% 吞吐重要得多。
