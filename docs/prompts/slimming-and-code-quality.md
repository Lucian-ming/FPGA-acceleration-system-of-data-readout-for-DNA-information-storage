## 2. 硬性约束（违反其中任何一条都要回滚）

1. **禁止 `git add -A` / `git add .`**；提交必须 `git commit -m "..." -- <路径>`。
   理由见 `CLAUDE.md`：索引是整棵工作树共享的，两个方向都出过事。
2. **禁止删除 `logs/`、`tests/stress_results/`、`tests/datasets/`、`data/` 下的任何文件。**
   那些是运行留证。归并、加 `README.md`、建 `superseded/` 子目录可以，删除不行。
3. **禁止改动 `sw/app/**`、`hw/ip/*/hdl/**` 的代码**（注释除外，且 RTL 只许加文件头注释）。
   这两处任何改动都会让 `hw/build/export/SHA256SUMS` 代表的「制品与源码同源」判据失效，
   而整文件 SHA 校验对此**完全失明**（`docs/03-status.md` §P0b 是踩过的坑）。
4. **禁止为了让检查变绿而放宽检查。** 发现 `check_*.sh` 报新问题：修问题，
   或在文档里写清为什么不适用。改判据阈值 = 作弊。
5. **禁止本轮引入新抽象**：不提取基类、不拆模块、不改目录结构、不批量改命名。
   本任务是「删掉不用的 + 说清在用的」，**不是重构**。
6. **`hw/experimental/` 下的文件不是全都没人引用。** `tools/run_sim.sh:207` 带着
   `five_to_four_decoder.v` 跑语法检查，直接删它回归立刻红。删这类文件要
   「先删引用行、再删文件、重跑回归」，三步同一个提交。见 `docs/19` §B2 的黄框。
7. **删任何文件之前先全库确认零引用**：
   ```bash
   grep -rIn "<文件名>" --exclude-dir=.git --exclude-dir=build --exclude-dir=xsim .
   ```
   把命令和输出贴进提交说明。
8. **`archive/submission_2025-11-07/`（221 MB，2025 赛季提交包）不许删也不许自行移动**，
   必须先问用户目标路径。这是唯一需要用户拍板的条目。
9. 推送后确认 `main...origin/main` 为 `0 ahead, 0 behind`。

## 3. 注释怎么写（这是本任务最容易做砸的部分）

本项目的注释**已经是资产**：`sw/app/stage1_dna.c` 的 `PIPE_WM_TX` 分支里一句注释省掉了一整轮板子，
`sw/app/echo.c` 里记着失败数字的那段注释防止了同一个错误被重犯。
**风格是「记录为什么与踩过的坑」，不是「说明这行在做什么」。**

| 要写 | 不要写 |
|---|---|
| 这个常量为什么是这个值、谁定的、改了会撞到什么 | `i++; // i 加一` |
| 这段修的是哪个编号的缺陷，失败时现象是什么 | 把函数名翻译成中文 |
| 「看起来可以优化，试过 N 次失败，原因是……」 | 无依据的「TODO 优化」 |
| 跨文件的隐式契约（谁先于谁执行、谁持有什么） | 重复类型声明已经表达的信息 |

**每条新注释都必须是可核验的事实。写不出依据就不要写。**
本项目已经因为「把推算当实测」（0.470 ms / Stage1 占 81%）付过一次代价——
在注释里塞一个想当然的数字是同一类事故。

## 4. 你还要交付两样东西

1. **把 `tools/check_repo_hygiene.sh` 从 7 项扩到 11 项**（`docs/19` §7.2）。
   **只写进文档的约定等于没有**——这是 `AGENTS.md` 代码卫生第 1 条。
   其中第 11 条（仓库内不得存在两份 SHA-256 相同的已跟踪文件）价值最高，
   它能自动发现 A1 那一整类缺陷。

   明确说出**查得了什么 / 查不了什么**，并且**必须验鉴别力**
   （故意注入一条坏数据，确认检查会红、退出码为 1，然后还原干净）。
   一条恒绿的检查比没有检查更糟。
2. **一份完成报告** `docs/benchmarks/` 之外的位置不合适，写成
