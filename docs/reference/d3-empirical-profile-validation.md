# D3 · 经验误差轮廓链路验证报告（extract → profile → mutate 闭环）

> 被测对象：`tools/extract_error_profile.py`（轮廓提取）与
> `tools/mutate_reads.py --profile-from`（轮廓驱动加噪），
> 即 `docs/reference/d3-wetlab-survey.md` §5.1 方案 A 的两个核心组件。
> 验证日期：2026-09-09。原始日志与中间产物：`logs/d3_profile/20260908T165006Z/`。
> 回归测试：`tests/test_empirical_noise_profile.py`（**17 项全绿**，40.2 s，零外部数据依赖）。
> 既有套件 `test_entropy_localization` + `test_payload_robustness_contract` 同步复跑 **19 项全绿**（209 s），无回归。

## 0. 结论速览

| 项 | 结论 |
| --- | --- |
| 提取器能否还原已知误差轮廓 | **能**。逐 cycle 替换率 Pearson r=0.9998，替换事件召回 99.879% |
| 加噪器能否忠实复现轮廓 | **修复后能**。往返闭环替换率偏差 +0.73%、Ti/Tv 偏差 −1.0% |
| 验证过程中发现的缺陷 | **2 个，均已修复并有常驻回归哨兵**（D3-1、D3-2，见 §3） |
| 本报告是否含真实湿实验数据 | **否**。全部结论基于**合成的已知真值**数据集，见 §1 事实边界 |

## 1. 事实边界（必读）

1. **本报告不含任何真实湿实验测序数据。** 验证用的是程序合成的、误差轮廓**已知**的
   数据集。这样做是刻意的：真实 FASTQ 没有真值可比，只能证明工具「跑得通」，
   无法证明它「算得对」。合成真值是目前唯一能对提取精度设阈的手段。
2. 因此本报告只回答「**工具链在给定轮廓下是否自洽且精确**」，
   **不**回答「本系统在真实 Illumina 数据上的鲁棒性如何」。后者必须等
   §5 的真实数据集接入后另行出报告，不得由本报告外推。
3. `--parametric-prior` 产生的轮廓带 `NOT_MEASURED` 标记，
   **不得**在论文/结题材料中表述为实测经验轮廓；该标记会传染给下游数据集
   manifest（`tests/test_empirical_noise_profile.py::test_l6_*` 守这条）。
4. 与 §5.1 原方案的一处偏离（属改进）：原计划用 `minimap2 -cx sr` 比对，
   实现改为**内置 k-mer 种子 + 带状 DP 比对器**，无外部生信工具依赖。
   代价是比对能力弱于 minimap2，因此提取器对**净插删超过 `--band`（默认 8）**
   的读段会判为不可信并丢弃。

## 2. 验证方法

合成数据集（`tests/test_empirical_noise_profile.py` 中可复现，seed=20260909）：

- 40 条 120 nt 随机参考 oligo，6000 条读段；
- 真值逐 cycle 替换率 `P(c) = 0.0015 + 0.030 * exp(0.045 * (c - 120))`，即 3' 端指数翘尾；
- 真值替换方向：转换（A↔G / C↔T）权重 4，两种颠换各 1 → **真值 Ti/Tv = 2.0**；
- 真值质量模型：Q(match) 38→30 线性衰减，Q(mismatch) = Q(match) − 10；
- 无插删（先隔离替换通道，避免比对错位污染判据）。

三步闭环：`noisy.fq --extract-> profile.json --mutate(clean.fq)-> mutated.fq --extract-> reprofile.json`。

## 3. 发现并修复的两个缺陷

### 3.1 缺陷 D3-1：Laplace 平滑把错误率地板注进了轮廓

**现象**：轮廓自报替换率 0.6883%，但用它加噪实际注入 0.7940%（**+15.4%**），
前 30 cycle 更是 0.1622% → 0.2778%（**+71.3%**）。轮廓文件对此**零告警**。

**根因（已定量证实，地板解释度 97.7~99.8%）**：原实现对整个 4×4×C 转移张量做
`counts + pc` 后按行归一，等价于给每一行注入常数错误地板

    floor = 3 * pc / (n + 4 * pc)      # n = 该 cycle 该 ref base 的观测数

n=1500、pc=0.5 时 floor = 0.1089%。而 JSON 里 `cycles/error_rate` 与
`aggregate/ti_tv_ratio` 写的是**原始计数**值，`cycles/substitution_matrix` 是**平滑**值，
加噪端只读后者——于是「轮廓宣称的噪声」与「实际注入的噪声」是两个东西。

**为什么危险**：偏差随数据量放大而缩小。要把早期 cycle（真值 ~0.1%）的地板压到
相对 5% 以下需 n ≳ 30000 观测/cycle/base，即 **>12 万条读段**。
低于此规模的轮廓全部被静默抬高——**中小规模验证集上最毒**。

**修复**：伪计数只平滑「已发生替换后错成哪个碱基」的 3 选 1 **方向分布**，
「错/不错」的二分严格取原始计数。伪计数的本意就是避免低覆盖 cycle 出现
「某个替换方向概率为 0」，而不是凭空发明一个碱基错误率。
新增 `--rate-pseudocount`（默认 **0** = 忠实实测）供确需平滑错误率时显式开启。

### 3.2 缺陷 D3-2：方向伪计数向均匀收缩，把 Ti/Tv 稀释 15%

**这个缺陷是修完 D3-1 之后才暴露出来的**：错误率闭合了，Ti/Tv 仍从 2.0405 掉到 1.7350。

**根因**：方向伪计数 `off + 0.5` 是向**均匀分布**收缩，而均匀方向的 Ti/Tv = 1/2 = 0.5。
早期 cycle 每 ref base 只有 **2.43 次**替换事件，伪计数总量 3×0.5 = **1.5**，
先验占了 38% 权重，方向偏好被大幅拉平（后段 26.22 次/cycle 则几乎不受影响）。

**修复**：方向伪计数总量仍为 `3*pseudocount`，但按**该数据集自身的聚合方向分布**分摊，
即向「本数据集的化学偏好」收缩而非向均匀收缩。依据：替换方向偏好来自化学
（转换天然多于颠换），基本与 cycle 无关；随 cycle 变的是**错误率**，不是**方向**。

## 4. 判据的鉴别力（R9）

新增常驻自检字段 `smoothing.self_check`，两个量各自是一个缺陷的**唯一探针**：

| 判据量 | 守什么 | 故障注入实测 | 修复版 |
| --- | --- | --- | --- |
| `sub_rate_inflation` | D3-1 | `--rate-pseudocount 0.5` → **+14.37%** → `[FAIL]` | +0.00% |
| `ti_tv_rel_dev` | D3-2 | 方向先验退回均匀 → **+15.09%** → `[FAIL]` | +0.43% |

容差均为 2%，不一致时 `print_summary()` 打 `⚠ [FAIL]` 告警。

**口径本身就是教训**：`ti_tv_rel_dev` 必须用**逐 cycle** 矩阵计算。
最初写成用**聚合**矩阵算——聚合计数大、几乎不受平滑影响，偏差只有 0.18%，
而同一时刻加噪闭环里 Ti/Tv 已经掉了 15%，判据全程绿灯。

对照：以下这些量在 D3-1 注入前后**逐位不变**，全都看不见该缺陷——
`counts.substitutions`(4956→4956)、`aggregate.ti_tv_ratio`(2.040→2.040)、
`cycles.error_rate`（逐位相同）。因为它们报的是原始计数，而缺陷在平滑矩阵里。
这与 `AGENTS.md` 记载的 SE150/SE250 几何教训（15 个产物 14 个逐字节不变、
只有 `wm_regions.hex` 有鉴别力）是同一类问题：**选错观测量 = 没有测试。**

### 4.1 文件级故障注入：整份测试文件确实会变红

把 `tools/extract_error_profile.py` 换回修复前的版本（sha `f1f708cb…`），
`tests/test_empirical_noise_profile.py` **16 项中 7 项变红**（4 failures + 3 errors）：

```
ERROR: test_l2_matrix_implies_reported_rate                       (无 self_check 字段)
ERROR: test_l2_self_check_present_and_passing                     (无 self_check 字段)
ERROR: test_l4_fault_injection_uniform_direction_prior_is_caught  (无 rate_preserving_matrix)
FAIL : test_l2_cycle_matrix_preserves_titv                        (逐 cycle Ti/Tv 被稀释)
FAIL : test_l3_round_trip_rate_closes                             (往返替换率 +14.9%)
FAIL : test_l3_round_trip_titv_closes                             (往返 Ti/Tv −16.6%)
FAIL : test_l4_fault_injection_rate_floor_is_caught                (旧版无 --rate-pseudocount)
Ran 16 tests in 26.444s / FAILED (failures=4, errors=3)
```

修复版同一套测试：`Ran 16 tests in 36.282s / OK`。文件已按 sha256 核验恢复。

**关键观察**：L1 的 4 项（提取还原度）在缺陷版下**仍然全绿**。
因为这两个缺陷藏在**平滑后的矩阵**里，而 L1 查的原始计数一个 bit 都没变。
只写 L1 的话，这套测试会给缺陷版发一张全绿通行证——这正是 R9 要求鉴别力的理由。

## 5. 尚未完成（明确的事实缺口）

1. **未接入任何真实外部数据集**。§1 的边界因此成立。下一步应取
   Erlich/Organick 公开 FASTQ 走一遍 `--bam` 或 `--fastq` 路径，
   并核对提取出的 Ti/Tv、翘尾 beta 与文献值是否同量级。
2. **插删通道未做真值验证**。本轮合成数据 InDel 速率为 0（为隔离替换通道）。
   已知现象：真值 0 插删时，内置比对器仍虚报 3 个插入（0.00042%），
   系带状 DP 在高错误率末端 cycle 的虚假 gap。该量级可忽略但非零，
   **插删轮廓的还原精度目前无实测依据**。
3. **`--band` 默认 8 的丢弃率未量化**：净插删超过 8 的读段会被静默判为不可信丢弃，
   在高插删数据集上会使轮廓偏向「低插删」。需补一条丢弃率统计与告警。
