## 11. 根因分析（**假设，未证实**）：`send_result()` 的结果发送是**无界重试**

这一节是代码级的候选解释，**不是已证实的结论**。它之所以值得单列，是因为它能同时解释
§4 里**全部**观察到的现象，且不需要引入"两个独立故障"。

### 11.1 代码事实

`sw/app/echo.c` 的 `send_result()` 由 **`poll_callback` 的 `PROC_DONE` 分支直接调用**
（`echo.c:527`），即运行在 lwIP 的回调上下文里。其中两处等待**没有任何时间上限**：

| 位置 | 代码形态 | 上限 |
| --- | --- | --- |
| 发头部 | `for (;;)`，`tcp_write` 返回 `ERR_MEM/ERR_WOULDBLOCK` 就 `tcp_output` + `usleep(1000)` + `continue` | **无** |
| 发正文（8100 B） | `while (sent < result_size)`，`tcp_sndbuf()==0` 就 `usleep(1000)` + `continue` | **无** |
| 等 ACK 排空 | `while (unsent \|\| unacked) && wait_ack_cycles < 2000` | **2000 ms** |

⚠️ 不对称正是可疑点：**最后一个等待被加了上限，前两个没有**。

### 11.2 它如何解释每一项观察

| 观察 | 解释 |
| --- | --- |
| `first.py` 下发后 900 s 无响应 | 板子卡在 `send_result` 里，结果永远发不出去 |
| 网络整体死（WSL/Windows 都不通、ARP 失败） | `poll_callback` 不返回 ⇒ **lwIP 不再处理任何 RX**，ping 自然不回应 |
| A9 一直 `Running` | 不是崩溃，是在 `usleep(1000)` 重试循环里转 |
| PC 落在 `usleep_A9` | 与该循环里的 `usleep(1000)` 一致 |
| **串口 0 字节** | 关键：`[RESULT] Sending…` 与 `[B29-DIAG] … retry #N` 都用 `xil_printf`，而 `fw_diag.h` 在 `FW_DIAG_LEVEL=1` 下把 `xil_printf` **编译成空操作**（只有 `FW_ERR_PRINTF` 在 1 级仍输出）。**所以卡在这里时串口必然是 0 字节** |
| 30 s 停滞看门狗没触发 | 看门狗在 `stage1_dna.c` 的 STAGE1 状态里；此时流水线已完成，代码在 `send_result` |

### 11.2b 全仓审计：无界循环**只有这两处**

对 `sw/app/*.c` 的全部 `for (;;)` / `while (...)` 逐条核对上限后，结果收敛：

| 位置 | 是否有上限 |
| --- | --- |
| `echo.c:802` 发头部 `for (;;)` | ❌ **无** |
| `echo.c:826` 发正文 `while (sent < result_size)` | ❌ **无** |
| `echo.c:869` 等 ACK 排空 | ✅ 2000 ms |
| `echo.c:314` 解析循环 | ✅ 每次循环消耗缓冲或 break |
| `stage3_decoder.c:335` `for (;;)` | ✅ 墙钟 `DECODER_CLEANUP_IDLE_TIMEOUT_US` |
| `main.c:350` `for (;;)` | 主轮询循环，本应在 |

⇒ 只盯着 `send_result` 是有依据的，不是先入为主。

### 11.3 触发条件（推测）

只要 TCP 发送窗口不再打开——对端不 ACK、链路瞬断、EMAC TX BD 耗尽——重试就永不退出。
正常 1007 轮能过，说明这是**低概率的瞬态**被无界循环放大成了永久挂死。

### 11.4 如何证实 / 证伪（**都需要换制品，须用户拍板**）

1. **加诊断**：用 `-DFW_DIAG_LEVEL=2` 重编，重试诊断就会打印，挂死时串口能直接看到 `retry #N`；
2. **加修复**：给两处循环加总超时（例如 30 s），超时就 `tcp_abort` 并回到 `PROC_IDLE`，
   让**下一次连接能恢复**——这同时把"挂死"降级成"单轮失败"。

⚠️ 两条路都会产生**新的 `fw_build_id` 与新制品包**，必须重做 G3 与 42 例的归属，
**不能与本次失败混为一谈**，也不是我单方面可以改的。

### 11.5 与本文结论的关系

即使 §11 的假设成立，**本次长稳仍然是 FAIL**：无界重试是固件缺陷，不是测试方法问题。
在真实 8 h 达标前，v1.1 不得被宣布长稳通过。

## 12. 如果重跑仍失败：**v1.2 最小修复提案**（只写方案，**未实施**）

⚠️ 本节是**待用户拍板的提案**，不是已经做的改动。它会**改变交付物**（新固件包、新 `fw_build_id`），
因此必须先获批。

### 12.1 改什么（只动 `sw/app/echo.c` 的 `send_result`）

1. **给两处无界循环加墙钟上限**（与 `stage3_decoder.c` 的既有写法一致）：
   - 发头部 `for (;;)`：超过 N 秒未成功 ⇒ `tcp_abort(conn->tpcb)`，清空连接状态，`return`；
   - 发正文 `while (sent < result_size)`：超过 N 秒未前进 ⇒ 同上。
   - 建议 **N = 30 s**（正常整轮 5 s，8100 B 发送在毫秒级；30 s 有 6 倍余量）。
2. **把重试诊断从裸 `xil_printf` 改成 `FW_ERR_PRINTF`**：这样在 `FW_DIAG_LEVEL=1`
   下**也能留下证据**。现在正是因为用了裸 `xil_printf`，挂死时串口才是 0 字节。
3. **超时后回到 `PROC_IDLE`**：把"永久挂死"降级为"**单轮失败**"，下一次连接能恢复。
   这符合长稳本身的观察目标（应看到失败轮，而不是整机失联）。

### 12.2 不改变什么（必须守住）

- **不动任何判据**：架构判据、系统判据、SHA 仲裁逻辑一行不改；
- **不动 RTL**：`hw/` 不变 ⇒ **同一个 bit**（`2ec76c7d…`），不需要重跑 Vivado；
- 不改协议字段、不改结果格式。
