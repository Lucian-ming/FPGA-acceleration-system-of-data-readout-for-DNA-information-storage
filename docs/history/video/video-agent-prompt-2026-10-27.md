## 二、必须讲清的四个阶段（技术事实，不得改动）

### 输入与几何

- 测序读段：SE150，每条 150 个碱基（150 bp），对应 300 bit（每个碱基 2 bit）。
- 参考序列/水印：40,500 个 2-bit 符号 = 81,000 bit。
- 切成 50 段，每段 957 bp；搜索步进 807 bp；相邻段重叠 150 bp。
- 候选起点：0..40,350（共 40,351 个），旁白可说“四万多个候选起点”。

### Stage1 滑动相关（滑窗比对）

- 把一条读段放到每一个候选起点，逐个碱基比较（比较 2-bit 符号）。
- 得分 = 匹配的碱基符号数，范围 0..150，不是 0..300；正确位置峰值约 75/150，噪声位置约 59–62/150。
- PL 每个周期并行比较 16 个窗口；选优树 16→8→4→2→1，逐级打拍；每批 64 条读段并行处理。
- 输出：300 bit 码字 + 16 bit 全局位置 + 10 bit 得分。
- 可视化建议：参考双链局部“解开”，读段单链沿参考滑动；匹配处画氢键/高亮，错配处标红叉；旁边同步画出得分曲线和 16 路并行条。

### Stage2 差分投票

- 每条读段的 300 bit 码字按起点摊回 81,000 位的投票数组；上下两层各 40,500 位。
- 每个位置是 10 位有符号累加器：读到 1 加一，读到 0 减一；饱和范围是 -512..+511。
- 每批 64 条读段处理完，票数大于零判为 1（vote>0 → 1）。
- 之后 PS 把结果与水印逐字节 XOR（LSB-first），得到 81,000 位共识码流。
- 不要把它画成“逐位多数表决”；它是带符号累加后看符号。

### Stage3 反稀疏化

- 每 5 bit 一组：`grp = [b4 b3 b2 b1 b0]`。
- 输出 4 bit：`r = grp[4:1] XOR {4{grp[0]}}`。
- 最低位 b0 是取反标志：b0=0 时 b4..b1 原样输出；b0=1 时四位全部取反。
- 81,000 bit → 64,800 bit = 8,100 B；实现每拍 64 bit 进、40→32 bit、64 bit 出，1,013 拍。
- 可视化建议：突出 b0 扇出到四个 XOR 门，分别演示 b0=0 和 b0=1 两种情况。

### LDPC 纠错

- DVB-S2 R=5/6；码字 64,800 bit = 54,000 信息位 + 10,800 校验位。
- 硬判决 flooding Min-Sum：变量节点与校验节点之间迭代传递消息；每轮后做硬判决并检查 10,800 个校验方程（syndrome）。
- 只有 syndrome = 0/10,800 才接受；不收敛或超时则保留 Stage3 原码字，由客户端拒绝（SAFE_NOCONV）。
- syndrome 每轮重新计算，可能波动；绝对不要画成“单调递减”。可以用“≠0 → 下一轮 → 0”并标注“示意”。
- 可视化建议：6 个变量节点（圆）+ 4 个校验节点（方）的小 Tanner 图，V→C、C→V 消息脉冲；右侧固定显示迭代计数和 syndrome 面板；最后给出“接受/拒绝”两条分支。

### 结果与判据

- 板端回传 8,100 B 的 64,800 bit 结果码字；客户端提取 54,000 信息位，按 `input_bytes` 截断为最终载荷（上限 6,750 B）。不要把 8,100 B 说成载荷上限——它是结果码字。
- 双层硬判据：板端 syndrome 全零 + 载荷 SHA-256 与期望一致；两者都通过才算成功。
- 四级逐级取证（水印/Stage1/Stage2/Stage3）只用于定位错误，不参与最终裁决。
- 性能：P4 26.5 s → P16 8.95 s（2.97×）→ 每拍 2 碱基 K=2 6.06 s（1.50×）→ 定版约 5.1 s（核心处理合计约 5.2×）；上传段 4.27→0.40 s（10.7×）。
- 42 例载荷：26 PASS / 16 SAFE_NOCONV / 0 静默错误；不能写成 42/42 通过。
- 长稳：v1.1 8 h / 1736 轮 / 0 失败；2026.1 2 h / 262 轮 / 0 失败；两者版本与时长必须分开标。
- 平台：Zynq-7000 XC7Z020（BKB220），PL 100 MHz，PS 裸机 lwIP/DMA，上位机 Python GUI；Vivado/Vitis 2026.1。
