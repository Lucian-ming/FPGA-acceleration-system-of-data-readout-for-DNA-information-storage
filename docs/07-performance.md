# 07 · 性能口径与基准

## 1. 当前实测事实

当前板测模型为：

```text
t = 4.93 s + 0.9396 ms × 记录数
```

SE250 全量 129,600 条记录的板端计算约 217.47 s。这个模型描述当前 profile 和当前板，不是理论上限。

已有 CPU/FPGA 对照显示：优化 C 单核/多核可能快于当前未展开 Stage1 RTL。因此项目不能用未优化 Python 作为唯一基线，也不能先宣称 FPGA 加速领先。

## 2. 计时口径

每个版本必须同时报告：

```text
FASTQ 读取 / TCP 上传 / DMA 入 / Stage1 / Stage2 / PS XOR /
Stage3 / DMA 回传 / TCP 接收 / LDPC / 端到端
```

至少重复 3 次，报告中位数、范围、记录数、输入哈希、板卡和工具版本。

## 3. Stage1 瓶颈

当前 Stage1 在读段维度批量并行，但碱基维度仍有串行扫描，是首要优化对象。候选实验：64×4、64×8、128×4。每档必须记录 LUT、FF、BRAM、DSP、WNS/WHS、板端周期、端到端耗时和功耗。

## 4. 公平 CPU 基线

CPU 必须使用同一输入、同一正反向规则、同一输出判据和同一记录数。至少包含：

- Python 参考实现；
- 优化 C 单核；
- 优化 C 多核；
- 当前 FPGA；
- 优化后 FPGA。

## 5. 禁止的性能结论

以下没有实测前不得写成事实：

- “FPGA 比 CPU 快多少倍”；
- “能效低多少倍”；
- “支持任意 DNA 数据”；
- “线性规模可无限扩展”。
