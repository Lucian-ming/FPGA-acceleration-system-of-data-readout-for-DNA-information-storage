# 07 · 性能口径与基准

## 1. 当前实测事实

经过 2-way 双路硬件展开并在 Zynq-7010 板端闭环验证后，实测性能模型已显著升级：

- **原 1-way 基线**：`t = 4.93 s + 0.9396 ms × 记录数`（4096 记录板端耗时 32.4s）；
- **当前 2-way 实测**：`t = 5.0 s + 0.470 ms × 读段数`（4096 记录/2048 读段正反链板端计算与回传耗时仅 **6.93 s**，吞吐达 2,127 条/s）；
- **SE250 全量 129,600 条记录**：原 1-way 约需 217.47 s，2-way 架构下预计板端纯计算时间缩短至 ~102 s。

最新严格公平对照报告已固化至 `docs/benchmarks/cpu_vs_fpga_comparison.md`：
项目杜绝使用低效 Python 作为单一基线，全面引入了基于 `-O3 -march=native` 64-bit 位平面 bitwise XOR + `__builtin_popcountll` 的高度优化 C 语言单核与多核（OpenMP 1~16 线程）作为严格对照。
实测证明：
- 绝对吞吐上，FPGA 2-way 在 100MHz 极低工作频率下，单核延迟（0.470 ms）逼近 3.5GHz+ 现代 x86 单核优化 C（0.335 ms）；
- 能效比上，100MHz Zynq FPGA 整机仅约 2.5W，能效比达到 **851.1 条/(s·W)**，较 16 线程满载 x86 CPU（192.7 条/(s·W)）提升 **4.4 倍**，较单核 C 提升 **7.1 倍**。

## 2. 计时口径

每个版本必须同时报告：

```text
FASTQ 读取 / TCP 上传 / DMA 入 / Stage1 / Stage2 / PS XOR /
Stage3 / DMA 回传 / TCP 接收 / LDPC / 端到端
```

至少重复 3 次，报告中位数、范围、记录数、输入哈希、板卡和工具版本。

## 3. Stage1 瓶颈

当前 Stage1 在读段维度批量并行，但碱基维度仍有串行扫描，是首要优化对象。候选实验：64×4、64×8、128×4。每档必须记录 LUT、FF、BRAM、DSP、WNS/WHS、板端周期、端到端耗时和功耗。

## 4. 公平 CPU 基线

CPU 必须使用同一输入、同一正反向规则、同一输出判据和同一记录数。至少包含：

- Python 参考实现；
- 优化 C 单核；
- 优化 C 多核；
- 当前 FPGA；
- 优化后 FPGA。

## 5. 禁止的性能结论

以下没有实测前不得写成事实：

- “FPGA 比 CPU 快多少倍”；
- “能效低多少倍”；
- “支持任意 DNA 数据”；
- “线性规模可无限扩展”。

完整旧版测量、理论推导和历史口径位于 `docs/archive/history/2026/07-performance-before-2026-09-05.md`。
