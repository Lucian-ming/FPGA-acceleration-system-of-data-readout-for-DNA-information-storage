# 07 · 性能口径与基准

## 1. 当前实测事实

历史板测模型为 `t = 4.93 s + 0.9396 ms × 记录数`，适用配置和边界见原始运行摘要。
它在 4,096 记录处约为 8.78 s，不是旧文混入的 32.4 s；旧阶段差异不能归功于一次展开。
SE250 全量约 217.47 s 也是旧配置记录，不外推为新版已测性能。

`tools/run_cpu_benchmark.py` 保留了优化 C 单/多核测量入口，但 FPGA 基线来自固定常量，
2-way 由基线除二、8-way 为预期值，功耗同样是估算。故
[比较草稿](../../../../benchmarks/cpu_vs_fpga_comparison.md) 已按 2026-10-20 要求删除（含笔记本 16 线程数据）；现行 CPU 基线见 [server-baseline](../../../../benchmarks/server-baseline-2026-10-20/README.md)。
撤回 2-way 已达到 0.470 ms/源读段、851.1 条/(s·W)、能效领先 4.4/7.1 倍等结论。
保存的多 payload dump 可以重新验证正确性，不能独立恢复原运行耗时。

下一步按 [15](resume-and-parallel-plan.md) W1-A 修生成器，再用原始板测文件复测。

## 2. 计时口径

每个版本必须同时报告：

```text
FASTQ 读取 / TCP 上传 / DMA 入 / Stage1 / Stage2 / PS XOR /
Stage3 / DMA 回传 / TCP 接收 / LDPC / 端到端
```

至少重复 3 次，报告中位数、范围、记录数、输入哈希、板卡和工具版本。

## 3. Stage1 瓶颈

当前 Stage1 在读段维度批量并行，但碱基维度仍有串行扫描，是首要优化对象。候选实验：64×4、64×8、128×4。每档必须记录 LUT、FF、BRAM、DSP、WNS/WHS、板端周期、端到端耗时和功耗。

## 4. 公平 CPU 基线

CPU 必须使用同一输入、同一正反向规则、同一输出判据和同一记录数。至少包含：

- Python 参考实现；
- 优化 C 单核；
- 优化 C 多核；
- 当前 FPGA；
- 优化后 FPGA。

## 5. 禁止的性能结论

以下没有实测前不得写成事实：

- “FPGA 比 CPU 快多少倍”；
- “能效低多少倍”；
- “支持任意 DNA 数据”；
- “线性规模可无限扩展”。

完整旧版测量、理论推导和历史口径位于 `docs/archive/history/2026/performance-before-2026-09-05.md`。
