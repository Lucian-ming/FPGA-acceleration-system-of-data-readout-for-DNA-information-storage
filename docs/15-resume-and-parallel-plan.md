# 15 · 中断恢复与全流程并行计划

> **⚠️ 2026-09-10：优先级以 [17](17-competition-strategy.md) 为准。**
> 本文 §6 R 表首行「2→4/8 个窗口位置展开」已关闭（4-way 完成、8-way 因资源证伪），
> 新的最高优先级是拆解 4.25 s 板端固定开销。冲突之处以 17 为准。

> 本文是当前执行队列；[13](13-final-delivery-roadmap.md) 保留终态门禁和广泛候选池，
> [11](11-optimization-plan.md) 保留优化原则，[16](16-interrupted-work-audit-2026-09-06.md)
> 记录此次接手证据。不再另起一份竞争性的“总计划”。

## 1. 最终目标

交付一套可复现的 Zynq DNA 信息存储读出系统，而不是一张漂亮的恢复图片：

1. 固定支持 profile、编码契约、输入 manifest、板卡配置和运行版本。
2. 实际板端回传经 LDPC 后，恢复 payload 与参考逐位/哈希一致；同时有四级 DDR 证据。
3. SE150、SE250 分开构建和验收，旧配置成功不能替代新配置回归。
4. 至少五种独立 payload 全部通过，真实 D0、合成 D1/D2、外部 D3 分栏报告。
5. 报告可重复的错误、覆盖度、长稳及故障恢复边界，失败样本不能从统计里消失。
6. CPU/FPGA 在同输入、同输出、同方向规则下比较 Stage1 与端到端；功耗实测独立列项。
   **2026-09-10 补充**：该比较的结论已经确定——本器件上 FPGA 不可能胜出
   （[17](17-competition-strategy.md) §1）。因此本条的交付物是**一张诚实的对照表加上
   原因分析**，不是一个正的加速比；把它当成待争取的指标会浪费剩余工期。
7. 提供一条新会话可执行的复现入口、制品清单和答辩材料，`main` 与 GitHub 同步。

性能目标不是预先编造某个加速比。先冻结公平基线，再用实测选择胜出的方向；
如果仍慢于优化 CPU，应明确交付“资源受限平台上的协同读出系统”及真实取舍，
不能把能效或通用性换成另一个未经验证的宣传口径。

## 2. 现状评价

- **闭环是真的，优势还没证明。** 旧版 SE150/SE250 G3 有价值，不能推广成新版所有配置已通过。
- **报告可信度是当前最大风险之一。** FPGA 的 0.470 ms 是脚本除二计算，2.5 W 是常量；
  用它们宣称板测能效优势，会直接损害项目可信度。
- **资源结论过早。** 旧报告的 54 BRAM/4,254 Slice 被当成新 2-way 数据，不能据此判死 4-way。
- **泛化不是零进展，也没完成。** 已有五份 dump、四份哈希通过、一份高熵失败，
  比只有原图强，但失败根因不能凭“高熵”两个字定性。
- **鲁棒性扫描可复用，但不能盖 G5 章。** 最佳方向、大数投票与板端 both 独立投票不等价；
  单次成功不是成功率，前缀读段扫描不等于随机覆盖度实验。
- **并行最大的风险不是 Agent 不够多。** 是公共文件、索引、构建输出和物理板卡的争用，
  以及子 Agent 把未经验证的假设写进权威文档。

## 3. 总体依赖与并发预算

默认四个槽位：`main` 加最多三个子 Agent。只在同一 main checkout，遵守 [14](14-git-parallel-workflow.md)。
任务卡由 main 分配**明确路径**；未获分配的公共文件禁止写入。

```text
W0 接管、冻结证据、分配路径
 ├─ W1-A 基准/计时可信化 ──→ W2-H 上位机瓶颈优化
 ├─ W1-B 数据与板端等价模型 → W2-D 高熵定位/鲁棒性
 └─ W1-C RTL/资源审计 ─────→ W2-R 候选最小实验
                 ↓ main 审核、相关单测、提交、冻结源码
W3 单一构建/接口回归 → 板卡独占验收 → 公平性能与能耗复测
                 ↓
W4 多 payload/多种子/长稳/错误恢复 → W5 文档、制品、答辩收口
```

硬件候选的分析/TB 可与 W1 并行，性能改造合入生产线必须等 T0 计时口径稳定。
没有功率仪时，软件任务继续；功耗门禁保持未关闭，不用估算补数。

## 4. W0：接管与防止再次丢失

1. 运行仓库绑定远程门禁，登记 `main`，查看 Git、看板和进程；重复核验本轮审计的时效性。
2. 逐文件登记脏改动、运行任务、负责人；有存活写入者先协调，不能直接清看板或删除文件。
3. 冻结输入与制品 SHA、基线 commit、板卡 profile；对源码归属不明的制品标记待核验。
4. 不重复全库审计。以 [16](16-interrupted-work-audit-2026-09-06.md) 为线索，直接进入以下三个任务。

验收：无人占用同一写入范围，无隐藏 Git writer；板卡、长构建和 benchmark 都有唯一持有人。

## 5. W1：三个独立先手任务

| 任务/Agent | 独占写入范围（启动前 main 复核） | 必须完成 | 验收 |
|---|---|---|---|
| A `bench-contract` | `tools/run_cpu_benchmark.py`、新的 benchmark 专属测试文件 | 实测/历史/估算分型；原始 JSON 与 run-id；明确源读段和板端记录数 | 无板端文件时不生成“FPGA 实测”；无功耗输入时显示缺失，不计算实测能效 |
| B `payload-contract` | `tools/run_multi_payload_regression.py`、`tools/run_robustness_scan.py`、新的数据测试文件 | 严格 dump 格式；golden/board/check-dumps 分离；结果/种子/哈希落盘；生产端与参考比较隔离 | 长度/非法字节/错 payload 必须失败；保存 dump 复核仍是 4 PASS + 1 FAIL |
| C `rtl-evidence` | 新建 `docs/benchmarks/stage1-candidate-audit.md`（本阶段不改生产 RTL） | 审计现有 1/2/4/8-way 文件、顶层/IP 打包引用、时序及报告来源 | 说明展开的是哪个循环；哪些是真正生效源码；不得把文件名、编译通过当实现成功 |

各任务均需先查看本目录下的 `AGENTS.md`。A/B 不得自动覆盖 `docs/03`、`07`、
共同报告或 `hw/build/export`；生成结果写独立 `logs/<任务>/<run-id>/`，由 main 审核再更新摘要。

A 的具体测试：

- 用小型固定输入验证 CPU 单/多核返回相同位置、得分和 tie-break，不能只比较耗时。
- 显式区分 `source_reads=N`、`orientation=both`、`records=2N`，计时单位必须写全。
- Python 抽样外推、CPU wall time、板端寄存器周期、端到端时间不得混成同一列。
- 用计时边界测试证明上传、等待计算、接收、LDPC 是否重叠；重叠段不能直接相加。

B 的具体测试：

- `check-dumps` 不访问板卡，不把本次译码耗时当旧板测耗时，缺文件不能静默跳过后宣布全绿。
- 64,800 B 的 ASCII/位数组必须全文件检查，8,100 B packed 必须固定 bitorder。
- 首先建立“板端等价模式”：both 每条独立过阈值、逐票饱和、几何、位序、tie-break 一致。
- 同时保留旧最佳方向软件模式但另行命名；其曲线不能用于声称硬件鲁棒性。
- 记录高熵样本与其他样本的不同门限（目前 60 与 67），比较中不能隐藏这个变量。

## 6. W2：带预算的广泛探索

W1 审核后重新分配文件，避免 B 与主机优化者同时改同一 Python 模块。

### H：上位机

先拆计时，再优化，不先大拆架构。目标包括 FASTQ/水印预处理缓存、批量打包、减少复制、
流式接收、C LDPC 开销和 UI 后台任务。缓存键含输入哈希、profile、代码/参数版本；
断连、超时、取消、重复任务必须有回归。每次只改一个可归因因素。

验收：同输入逐位一致，报告 p50/p95、内存峰值和端到端收益；
只让 GUI 更流畅但板端仍慢，也应如实记为交互收益，不能声称计算加速。

### D：高熵失败与数据扩展

依次比较生成器编码自检 → 参考比对 → 板端等价软件链 → 每级 DDR → LDPC。
先找首次不一致，再判断是算法能力、参数、投票溢出/饱和、几何还是实现错误。
不得直接通过降低门限或换样本掩盖失败。

仅有一份真实 DNA 仍可推进：保留 D0 原始真实读段；D1 改变 payload 并重新编码；
D2 从明确基底注入受控噪声。随机 payload 要多个种子，不能把“同一模板的多个变体”
说成多个独立湿实验。D3 外部真实数据获取可作为独立资料任务，记录许可与编码兼容性，
不阻塞 D1/D2。

### R：候选池与筛选规则

| 未被证伪方向 | 最便宜的验证方式 | 继续条件/主要风险 |
|---|---|---|
| ~~2→4/8 个窗口位置展开~~ **已关闭** | 4-way 已完成（1.929x，88.0% LUT，WNS +0.246 ns）；8-way 外推 ~125% LUT 放不下 | ❌ 不再投入，见 [17](17-competition-strategy.md) §2.1 |
| **拆解 4.25 s 板端固定开销（新增 P0）** | PS 侧分阶段插桩：连接/CAPS/CONFIG/水印展开/BRAM 预载/Voter 初始化/DMA 配置/Stage 2.5 软件异或 | 占小规模任务 63% 且从未被测量；其文档解释与实测差约 3,000 倍 |
| **软信息喂 LDPC（提级）** | 输出 top1-top2 置信度而非硬判决 | 正确性维度收益，不受性能死局影响 |
| 减少读段 batch 换更多窗口并行 | 周期/存储端口预算 | 比较相同总资源下吞吐，不把并行数本身当收益 |
| 水印窗口复用、banking、预加载 | 访存周期计数与冲突 TB | 先证明访存是瓶颈，避免增加 BRAM 后时序恶化 |
| 频率提升、流水级重排 | 关键路径报告、接口延迟 TB | 正 WNS/WHS 并板测；改时钟后重新校准超时 |
| 精确提前停止/上界剪枝 | 参考模型逐位置比较 | 不改变最优解与并列规则；64 lane lockstep 下单 lane 提前退出未必省周期 |
| 双缓冲/传输与计算重叠 | timeline、队列和 DMA ownership 模型 | 确有可隐藏时延；DDR/cache/重启故障风险高 |
| 压缩/紧凑传输、减少 DDR 往返 | 字节数和 CPU 打包耗时测量 | 总收益为正；跨端协议改动必须三方同步 |
| 自适应阈值、方向配对、置信投票 | 多 payload、多种子等价软件消融 | 属于算法变更，不是无损实现优化；需重开正确性边界 |
| 覆盖度早停、按需追加读段 | 固定随机子集与成功概率 | 不能假设 N 越大必定更好，不能只测 FASTQ 前缀 |

每个候选先给不超过半天人工分析/小实验预算；main 根据正确性、收益、资源、实现复杂度
排序，每次最多推进两个重型候选。预算耗尽状态是“未决/延期”，不是“证伪”。
只有具体反例或该配置资源/时序失败，才能在相应范围内判失败，不能排除整个方向。
失败需保存参数、命令、首次错误和下一步，后续避免重复消耗 token。

## 7. W3：构建、上板与公平测量

1. main 收齐写入、审核 diff 和相关测试，提交推送；冻结具体源码 commit，暂停相关源码写入。
2. 构建者独占 Vivado/共享输出。执行 [08](08-verification-plan.md)、[09](09-board-build-and-acceptance.md)
   对应回归，不臆造“只需一次命令”。接口变化必须测试真实寄存器序列、FIFO 延迟、
   AXIS 背压、DMA/DDR 边界和连续重启。
3. 每个 profile/候选独立产物目录；记录工具版本、输入 manifest、实际实现报告及 SHA256SUMS。
   检查 XSA/bit/ELF/BOOT 关联后再装载，失败候选不得覆盖最后可用制品。
4. 板卡独占；无板卡时只停在仿真/构建层。采集原始串口/TCP、四级 DDR、最终哈希。
5. 统一输入和正确性边界下，CPU 单/多核、基线 FPGA、候选 FPGA 各热身后至少重复 3 次，
   重要结论扩展至 10 次以上，报告中位数、范围/尾延迟；没有重复分布不得报告 p95。
6. 测量期间禁止其他 Agent 做 CPU 满载、综合或占网 benchmark；可继续文档和轻量审计。
7. 功耗明确板级输入、CPU package/整机的测量边界、空闲/负载及仪器采样；
   不同边界只并列展示，不计算能效优势。分别报告板端和包含上位机的端到端代价。

验收：新版本配置清楚、逐级/最终正确，实测原始数据可重算结论。未达到收益目标可回退
候选但保留实验；main 负责选择基线，不让子 Agent 各自宣布“最优”。

## 8. W4：泛化、鲁棒性与系统回归

- 五种独立 payload 全通过后，再扩展高熵、尺寸、编码种子；失败率按样本与随机种子报告，
  “四过五”仅是五个样本的结果，不代表总体可靠率 80%。
- substitution/insertion/deletion 分开，再做混合；报告注入前已有的真实噪声及实际操作数。
  如果插删后裁剪/补齐到 150 bp，必须命名“插删加定长适配”，不能宣称原生变长支持。
- 覆盖度用 `N × read_bps / reference_nt`，N 是源读段，不因发送双向翻倍；
  多种子随机子集、阈值固定/自适应分别跑，报告成功率和区间。
- 只有有真/假标签与 FP/FN 定义才称 ROC；留存率曲线不是 ROC。
- 检查连续任务、取消、断连恢复、错误协议、超时、极限输入、温度/长稳；
  运行日志保留失败分类和所有分母，沿用 [12](12-stress-analysis.md) 口径。

## 9. W5：最终收口与中断续接

main 对照文档 13 的 G0～G8，一项项标注通过/失败/未测及证据路径，不能批量打勾。
同步 `03/07/09/10` 与 README，只保留当前结论；历史报告明确归档，脚本不能再覆盖权威摘要。
准备 clean checkout 复现记录、演示输入、制品/许可证清单、失败边界和答辩图表。

每个任务最迟在阶段结束或 30～60 分钟长任务检查点交接以下内容：

```text
任务 ID / Agent / 基线 commit / 独占路径 / 进程与板卡占用
已做改动 / 命令及退出码 / 原始结果路径 / 判据 / 未解决问题
下一条可执行命令 / 恢复前必须核验的文件 / 预计剩余工作
```

动态信息进看板，持久结论进本任务报告；失败和未完成也必须有负责人。
交付必须同时完成 Git 同步、Agent 看板回收、资源释放和残留清点。
给新主会话的可直接发送文本见 [监督提示词](prompts/main-resume-supervisor.md)。
