# 片上 LDPC：L4 译码器原型（功能 + 时序，2026-10-14）

L4 的目标是「译码器 RTL 原型 + 对软件黄金验证」。结论：**功能对得上黄金，时序在 100 MHz 收敛。**

- RTL：`hw/experimental/ldpc_decoder_p1.v`；testbench：`hw/experimental/tb_ldpc_decoder_p1.v`
- 架构：**p=1 边串行 flooding Min-Sum**（见[架构决定](../reference/ldpc-architecture-decision-2026-10-14.md)）
- 器件 `xc7z020clg400-2`，时钟约束 100 MHz；流程 `docs/submission/skill/fpga-timing-probe/ooc_probe.tcl`（`SYNTH_IMPL=1`）
- 留证：`logs/vivado/ldpc-dec{3,4,5}.stdout` 与 `logs/vivado/ldpc-decoder/synth_*`（`logs/` 忽略区）

## 1. 功能：对黄金逐位相同

黄金集由软件参考实现（`clients/python/native_ldpc.py`）在 **14 个实测回传样本**上生成：
**8/14 收敛**，8 个收敛结果**码字 SHA 全同**（`53ba32145df35acd`），轮数分布 4~47。
生成脚本与数据：`logs/ldpc/golden/`（`build_golden.py`、`summary.tsv`、`in_*.hex`、`out_*.hex`）。

iverilog 仿真结果：

| 样本 | 结果 | 轮数 | 位不符 |
| --- | --- | ---: | ---: |
| `013_se150_16384` | **PASS** | 4 | **0** / 64,800 |
| `008_se150_2048` | **PASS** | 5 | **0** / 64,800 |
| 合法码字回灌 | **PASS** | **0**（初始校验即返回） | 0 |
| `006_se150_1312` | 码字**逐位相同** | 25（黄金 28） | 0 |

### 1.1 ⚠️ 轮数**不是**有效判据（本项的一个判据错误，已纠正）

`006` 的 25 轮与黄金的 28 轮不同，**这不是缺陷**：黄金轮数出自**浮点**实现，而定点实现本就不该给出相同轮数。
`logs/audit/ldpc-fixedpoint.md` 早已记录同一样本 **Double 28 / W8 46 / W6 25、完整码字相同**。
⇒ **有效判据只有两条：收敛状态一致、输出码字逐位相同。** 轮数仅供参考，不得据此判 FAIL。

### 1.2 已复刻的四个易错语义

1. **`np.sign(0.0) == 0`** ⇒ 某行只要有任一 LLR 恰为 0，`row_signs` 即为 0，**该行所有消息全为 0**（不能当 ±1 处理）；
2. **min1 并列取"首个"出现**（按槽序），不是任意一个；
3. **`decoded = (llr > 0)` 是严格大于**，`llr == 0` 判 0；
4. **输入本身是合法码字时返回 0 轮**（初始 syndrome 校验）。

## 2. 时序：从 −1.663 ns 到 +0.680 ns

五代 OOC 的轨迹（全部为**布线后**；综合后的数字一律不采信）：

| 版本 | WNS | 失败原因 | 修法 |
| --- | ---: | --- | --- |
| ① | 失败 | `RAM has multiple writes via different ports in same process`（Synth 8-3391）：`llr_mem`/`decoded_mem`/`sum_mem` 在一个 process 里有装载写与更新写两条语句 | 合并为**单写口**（地址/数据 mux），各自独立成块，并显式 `ram_style="block"` |
| ② | 失败 | `sum_mem` 的 `ram_style="block"` 被判 Infeasible，落成 LUTRAM（`RAM64M × 8104`），撑爆 17,400 的 LUTRAM 上限 | `sum_mem` 在两个状态分支各有一条读语句 ⇒ 被当成**两个读口**；合并为单读口 + 地址 mux |
| ③ | **−1.663** | 关键路径 `row_q → llr_mem`：**20 级逻辑、11 个 CARRY4**，源头是常量除法 `/30` | ÷30 改乘倒数右移 |
| ④ | **−1.421** | 仍有 7 CARRY4 + 1 DSP（11 ns）；终点变成 BRAM 写使能 | 见 §2.1 结构性改写 |
| ⑤ | **+0.680** ✅ | — | — |

### 2.1 关键修法：用码的结构关系消掉除法/乘法/取模

行 `r` 与基地址 `x` 同属 `r mod 30` 桶。写 `r = 30a + ρ`、`x = 30b + ρ`，则

```
x + 30m ≡ r (mod 10800)   ⟺   b + m ≡ a (mod 360)   ⟺   m = (a − b) mod 360
```

⇒ 列地址 `= base_col + m`，其中 **`base_col = 10800 + 360t` 与 `b` 都预存在表里**（表项 26 位）。
每边只剩「9 位减 + 一次条件加 360 + 17 位加」，**没有除法、没有乘法、没有取模**。

该式已在 Python 里对**全部 10800 行逐行核对（零不一致）**，新表（`logs/ldpc/golden/bt_col_by_res.hex`）做了同样的自检。

## 4. ⚠️ 边界（引用时必须一起说）

1. **这是 OOC，不是整机。** 没有 Stage1、AXI、PS 互连的拥塞与跨模块路径。项目有实测案例：同模块综合后 +2.197 ns，**整机布线后只剩约 +0.2 ns**。加上 K=2 整机现仅 WNS +0.313 ns，**并入后能否保持必须实测**。
2. **仿真只覆盖 2 个收敛样本**（013、008）与回灌用例；**另外 6 个收敛样本与 6 个不收敛样本未跑**。
   不收敛样本应报"未收敛"，这条**还没验证**。
3. **未并入 AXI 地址图、未走主机协议**（L6），**未上板**（L7）。
4. **周期数未实测**：本设计的 45 轮时延估算（≈0.381 s）仍是公式推导，未经仿真或板端计数。
5. 表内容真实（从 H 生成），但**地址生成的扫描顺序**（每行扫一桶 20 项）是正确性优先的写法，未针对周期数优化。
6. 版本注释：`bt_by_res.hex`（旧格式）仍在 `logs/ldpc/golden/`，本版用的是 `bt_col_by_res.hex`。
