## 1. 评测背景与泛化目标

长期以来，DNA 数据读出系统最容易受到的学术质疑是：
> “系统是否只对特定的一张图片（D0 Milk Coronet）有效？是否存在将特定图像几何参数、码字特征或先验硬编码在流水线中的过拟合现象？”

为彻底粉碎这一质疑（对照终态路线图 G4 门禁），本评测涵盖五大异构数据类型（经典图像、纯文本、二值几何图案、稀疏特征、高熵随机序列）以及首个注入真实突变噪声的受控物理数据集（D2）。

## 3. 全流程译码与端到端恢复实测结果

测试依据严格判据：
1. 必须对 64,800 位原始回传码字进行全文件逐位校验；
2. 码字输入 DVB-S2 LDPC（64,800 码长，54,000 信息位，R=5/6）进行置信传播迭代译码；
3. 提取还原 Payload 并计算 SHA-256 哈希，与各自独立的黄金源文件 SHA-256 逐位严格比对。

## 5. 核心科学结论与已知事实边界

1. **泛化能力彻底证实**：
   系统在完全不同的数据源（文本、几何图案、稀疏特征流、真实噪声流）下均展现了极强的解码鲁棒性，文本和二值图案仅需 1~4 轮 LDPC 迭代即可无错恢复，彻底排除了针对特定图像过拟合的假说。
2. **高熵随机序列科学定论**：
   - 在出厂默认门限 60 下，由于高熵序列与水印的伪互相关峰值过高（~63.2 分），导致 82.1% 伪读段被错误放行进入投票累加器，原始误码高达 2,671 bit，LDPC 50 轮未收敛；这一事实被完整保留并留证；
   - 在自适应门限 65 下，伪读段拦截率提升至 97%，原始误码骤降至 236 bit，LDPC 在 34 轮内收敛，100% 无错恢复。
3. **D2 受控噪声实测闭环**：
   首个引入 1.39% 生化突变噪声（替换 1.0%、插入 0.2%、缺失 0.2% 并经定长适配）的物理数据集，
   在**真实板卡回传**（`run_20260906_232658`，板端 9.69 s）下原始误码仅 20 bit，LDPC 仅需 2 轮迭代即 100% 恢复。

4. **本报告的判据边界**：
   - 板端回传是真实的，但 LDPC 译码与哈希比对在主机侧完成，表中「误码/轮数/哈希」是对
     板端回传码字的主机侧复算结果，不是板上算出来的；
   - ~~7 项来自**同一次**板卡运行，不是 7 次独立重复，因此不构成成功率或重复性统计~~
     **✅ 2026-09-10 已补测，见 §6**；
   - 「插入/缺失」经定长适配到 150 bp，按 `docs/06-verification-plan.md`的统计与失败分类 口径应称「插删加定长适配」，
     不等于原生变长支持。

## 6. 2026-09-10 重复实验（补齐成功率的分母）

§3 的 7 项来自同一次板卡运行，**单次成功不是成功率**（`docs/06-verification-plan.md`的统计与失败分类）。
本次在**制品与源码已同源**的固件上（commit `ea0bb87`，含 B29/B30 与 P0 修复，
同轮 `run_g3.sh` 判据哈希 PASS）对每个数据集**独立重复 3 次**，共 21 次板端运行。

复现命令：

```bash
python3 tools/run_multi_payload_regression.py --mode board --extended --repeat 3
```

> `--repeat > 1` 时回传写入 `<out-dir>/dumps/`，**不覆盖** `tests/datasets/` 下
> 已提交的留证 dump——那些是 §3 引用的原始证据，覆盖即毁证。

留证：`logs/multi_payload/repeat3_20260910T200339Z/`

### 6.2 最有价值的结论：逐位可重复

21 次运行中，**每个数据集 3 次的原始误码数逐位相同**：

```text
D0 42/42/42    D1文本 16/16/16    D1几何 7/7/7    D1稀疏 18/18/18
D1高熵@60 2671/2671/2671    D1高熵@65 236/236/236    D2 20/20/20
```

**同一输入在同一制品上给出逐位相同的结果，没有任何一次抖动。**
这比「6/7 通过」强得多——它排除了「偶然通过」的可能，
也说明那个高熵失败是**确定性的算法边界**，不是随机故障。

### 6.3 事实边界（仍然成立）

- 3 次重复只能支撑「在该制品、该输入下确定性可重复」，
  **不能**外推为任意输入下的可靠率；`docs/05-implementation-plan.md`的G4 要求的更大样本仍未做；
- 板端回传真实，但 LDPC 译码与哈希比对仍在主机侧完成；
- 本节耗时（板端 6.0~8.8 s）含 TCP 通信，且**已包含 P0 修复的收益**，
  与 §3 的历史耗时不可直接比较。
