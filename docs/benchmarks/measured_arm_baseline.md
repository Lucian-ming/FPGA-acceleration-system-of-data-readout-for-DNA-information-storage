# 同片 ARM（Cortex-A9）纯软件 Stage1 基线：上板实测（2026-09-22）

> ⚠️ **2026-10-19**：文中引用的 `D:\dna_board_smoke\arm_baseline\` 原始日志已按用户要求清理，
> 目录内容不再存在。本文的测量结论与数字保留，引用原始日志的路径已失效。

> **结论**：同一颗 XC7Z010 上，单核 Cortex-A9（667 MHz，裸机，-O3 + NEON popcount）做 Stage1 比对
> **12.10 ms/记录**；PL（4-way @100 MHz，P13 固件）端到端 **0.2451 ms/记录**，**快约 49 倍**。
> 结果与主机参考**逐条相同**（1,024/1,024 条，正反两向的分数与位置）。

## 1. 为什么要这个对照

既有 CPU 对照是 i5-13500H（笔记本处理器），回答的是「FPGA 能不能打过 PC」——答案是只快于单核、慢于 16 线程
（[docs/03](../archive/history/2026/pre-bkb220-handoff-2026-10-10/status.md) P13）。**嵌入式场景更直接的问题是：把 Stage1 放进 PL，比留在同一颗芯片的 ARM 上跑好多少。**
这是同一器件、同一数据、同一判据下的对照。

## 2. 方法

| 项 | 内容 |
|---|---|
| 算法 | `sw/bench_arm/arm_align.c`，与 `tools/align_omp.c` 逐行同构：位平面 + 逐位置移窗 + popcount，全局滑窗 40,351 个位置 × 正反两向，并列取最小位置 |
| ARM 优化 | GCC 12（Vitis 2022.2）`-O3 -mcpu=cortex-a9 -mfpu=neon`；popcount 用 NEON `vcnt`（反汇编确认，GCC 对 `__builtin_popcountll` 在 ARMv7 会退化为库调用） |
| 运行 | 裸机 standalone BSP（与生产固件同一 BSP），**单核**（CPU0），D-cache 开；PL 不配置 |
| 数据 | SE150 FASTQ 前 N 条读段 + r0.83 水印，与 G3 同源；XSDB `dow -data` 写入 DDR |
| 计时 | ARM 全局定时器 XTime（333.33 MHz），只计比对循环；水印位平面准备另计（约 1.8 ms） |
| 判据 | 同一份 C 在主机 x86 上编译出参考答案，逐条比对 (s_fwd, p_fwd, s_rev, p_rev)，全部一致才采信耗时 |
| 复现 | `python3 tools/board/arm_baseline.py --reads 1024` |

**工作量可比性**：ARM 扫 40,351 个位置；PL 扫 50 区域 × 808 = 40,400 个位置，相差 0.1%。
一条「记录」= 一条读段的一个方向，与板端模型 `N_records = 2 × 读段数` 同口径。

## 4. 对照

| 实现 | ms/记录 | SE150 全量（103,616 记录） | 相对同片 ARM |
|---|---:|---:|---:|
| 同片 ARM 单核（实测） | 12.10 | ≈ 1,254 s（外推） | 1x |

## 5. 边界

- 单核结果；双核只给了理想上限，未实测。
- 功耗未测：「每焦耳」对比须等功率计。
- 端到端 PL 数字含 DMA/Voter/固定开销；ARM 数字只计比对。这对 ARM 有利，不影响结论方向。
