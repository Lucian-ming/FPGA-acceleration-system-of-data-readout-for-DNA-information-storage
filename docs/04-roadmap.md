# 04 · 总体路线图

## 当前阶段

G3、SE150/SE250 全量板级闭环已完成。项目进入“性能可证明、数据可泛化、上位机可交付”阶段。

> **2026-09-10 定位修订**：参赛口径与性能天花板见 [17](17-competition-strategy.md)。
> 该文证明本器件上 Stage1 展开已到顶（1.929x 即天花板）且端到端无法超过对照 CPU，
> 因此“性能可证明”的含义改为**可证明的真实收益与可证明的边界**，不是加速比。

## 阶段 S0：证据与基线

- 固定当前 bitstream/ELF/BOOT.bin 哈希；
- 建立 CPU 单核、多核和 FPGA 同输入基线；
- 压测增加失败分类与阶段级计时；
- 不修改真实数据集。

**出口：** 每次运行有输入哈希、分段时间、最终哈希和失败类别。

## 阶段 S1：时间优化

> **2026-09-11 状态更新**：本阶段原定的两件事都已完成，且结论与预期不同，
> 见 [17](17-competition-strategy.md) §5.5 与 `benchmarks/measured_4way_board.md`。

1. ~~拆解板端固定开销~~ **已完成**：根因是「一次 lwIP poll 只推进一个流水状态」，
   批量化后 5.284 s → 1.505 s（3.5x）。剩余 poll 空等约占 2,048 读段任务的 29%，
   压缩已尝试四次全部失败并放弃（[17](17-competition-strategy.md) §3.0.6）；
2. ~~Stage1 64×4 展开~~ **已完成并已上板**：仿真核心 1.929x、WNS +0.246 ns 收敛，
   板端哈希与 2-way 逐位相同；**但端到端每记录成本只降 1.218x**；
3. ~~Stage1 64×8/128×4 资源评估~~ **已证伪，不再排期**（LUT 88.0% → 外推 125%）；
4. **新的主瓶颈：占每记录成本 62.9% 的「其余」**（DMA / Voter / poll / 回写）。
   板端实测反解出 Stage1 只占 **37.1%**，而文档此前假定 81%。
   **继续加宽 Stage1 的收益已封顶**（即使无限快，端到端上限也只有 1.59x）。
5. **因此本阶段的下一步不是优化，是测量**：给 Voter 与 Stage3 加与 Stage1 同规格的
   独立周期计数器，先把 62.9% 拆开。没有仪表就调参数，本项目已付过四次学费。

**出口（已修订）：** 三级各自的板端耗时可独立读出，62.9% 有分解，
且分解结论与两条斜率反解的总量自洽。
**注意**：按 [17](17-competition-strategy.md) §1，本阶段的目标**不是**超过对照 CPU
（在本器件上不可能），而是让「时间花在哪」这个问题在三级粒度上有实测答案。

## 阶段 S2：方向 A 通用参数化

- 多 payload 重新编码和 manifest；
- 运行时读长/水印/几何配置；
- 错误几何在任务开始前拒绝；
- 至少 5 个 payload 通过最终哈希和中间级别检查。

## 阶段 S3：方向 B 错误鲁棒性

- substitution/insertion/deletion 注入；
- 0.5×/1×/2× 覆盖度；
- `score_min` 扫描；
- 输出恢复成功率、原始误码、LDPC 迭代和耗时边界曲线。

## 阶段 S4：上位机交付

- Python 参考实现、C LDPC、协议会话、GUI 模块化；
- 超时、断连、错误配置可诊断；
- 结果流式保存，报告自动生成；
- 全量数据、长稳和错误矩阵回归。

## 阶段 S4.5：瘦身与代码质量（2026-09-11 新增）

冻结之前必须先清理。工作树 1.7 GB 而已跟踪内容只有 36.8 MB，
`sw/app/` 有 21.9% 是 Xilinx 模板死代码，`hw/experimental/` 积了 13 个退休文件。
**这些缺陷都不会让判据变红**，所以必须靠单独的计划与脚本判据来清。
详见 [19](19-slimming-and-code-quality-plan.md)：S-1~S-4 为冷清理（无需板卡），
S-5 为热清理（改固件源码，必须重建 + 烧录 + G3 + 更新 SHA256SUMS，单次提交）。

**出口：** `du -sh .` ≤ 600 MB；卫生检查从 6 项扩到 10 项且全 PASS；
19 的每个条目编号都能在某个 commit message 里被搜到。

## 阶段 S5：竞赛冻结

冻结器件、制品、工具版本、演示数据、演示脚本和答辩数字。未实测的性能、功耗和通用性只能写成目标。
