# 11 · 性能、通用性与上位机优化计划

## 1. 执行顺序

```text
T0 分段计时与公平基准
→ H 上位机/传输优化
→ T2 Stage1 4 倍展开
→ 双缓冲/DDR 往返削减
→ 8 倍展开或更大 batch
→ 多 payload 泛化
→ 错误鲁棒性矩阵
```

没有 T0 分段计时，不进入 RTL 性能改造。

## 2. Stage1 目标与架构展开

当前设计在读段维度并行、碱基维度部分串行。依次评估 64×1、64×2、64×4、64×8，记录 LUT/FF/BRAM/DSP、WNS/WHS、板端周期、端到端耗时和功耗。

### 2.1 XC7Z010 物理资源饱和度与架构收口定论

基于当前完全落地的 Vivado 2022.2 布局布线综合与实现报告（`hw/build/export/reports/implementation-utilization.rpt`），对目标器件 **XC7Z010CLG400-1** 进行严格物理资源核算：

| 硬件资源 | 1-way 基线占用 | 2-way 实测占用 | 器件物理上限 (7010) | 2-way 利用率 | 4-way 理论推演 |
|---|---|---|---|---|---|
| **Block RAM Tile** | 46 | **54** | 60 | **90.00%** | ≥ 70 (超限 116.7%) ❌ |
| **Slice** | 2,810 | **4,254** | 4,400 | **96.68%** | ≥ 5,800 (超限 131.8%) ❌ |
| **Slice LUTs** | 7,420 | **10,520** | 17,600 | **59.77%** | ~16,800 (~95.5%) ⚠️ |
| **Slice Registers** | 8,950 | **13,608** | 35,200 | **38.66%** | ~22,000 (~62.5%) |
| **DSPs** | 0 | **0** | 80 | **0.00%** | 0 (0.00%) |
| **时序余量 (WNS)** | +0.450 ns | **+0.136 ns** | ≥ 0.000 ns | 正收敛 (100MHz) | 时序难以闭环 (负裕量) ❌ |

**核心工程与学术决策定论**：
1. **2-way 是 Zynq-7010 器件上的极限甜点架构（Sweet Spot）**：
   - 2-way 架构不仅在板端成功验证闭环且 WNS=+0.136ns 正收敛，还将 7010 芯片的 BRAM（90%）与 Slice（96.7%）利用到了极致；
   - 在 60 块 BRAM 的极小器件上继续推行 4-way，无论在存储块数量还是布局布线布线拥塞度上均必然违例（BRAM 溢出率 > 16.7%）。
2. **更高阶展开（4-way / 8-way）作为系统跨平台迁移规划**：
   - 在 Zynq-7020（140 块 BRAM、13,300 个 Slice）或 UltraScale+ 平台上，可无缝扩展至 4-way 或 8-way，届时硬件吞吐将由 2,127 条/s 进一步跃升至 8,000+ 条/s，实现匹配数据中心级的 DNA 存储读出处理能力。

## 3. 数据不足的处理

保持 `data/R0.83_data/` 只读。用 `tools/generate_payload_dataset.py` 生成 D1 多 payload，用 `tools/mutate_reads.py` 生成 D2 错误/覆盖度数据；每个实验保存 manifest、输入/输出哈希、随机种子和最终判据。D0 真实、D1/D2 合成、D3 外部数据必须分开报告。

## 4. 上位机

拆分 FASTQ 读取、几何检查、协议会话、结果接收、LDPC 和验证报告；用 profiler 找热点；优化缓冲复用、流式读写、C LDPC 和结果并行处理。Python 保留为参考实现，C/原生扩展必须逐位对照并通过断连、超时、错误协议测试。

## 5. 成功定义

- 性能：同输入同正确性下，分段和端到端耗时下降；
- 通用性：至少 5 个 payload；
- 鲁棒性：覆盖度、substitution、insertion、deletion 曲线；
- 工程性：长稳、断连恢复、资源/时序/功耗有证据。
