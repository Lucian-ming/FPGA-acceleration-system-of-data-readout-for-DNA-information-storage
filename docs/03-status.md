# 03 · 当前状态与未关闭问题

> 更新：2026-09-05。本文只保留当前有效结论；历史故障、旧版本口径和完整时间线移至 `docs/archive/history/2026/`。

## 1. 当前结论

- **G3 已闭环**：SE150 与 SE250 均在目标 Zynq ECO(R6) 板上完成真实 TCP → PL → DDR → LDPC → 图片哈希闭环。
- **SE250 全量已闭环**：129,600 条记录、64,800 条源读段，板端结果 8,100 B，图片 SHA-256 为
  `fcd0cf90bd680e7bbdc203e3398119504da0897acac9e2117008b4efb6b1f2c3`。
- **连续任务已闭环**：跨规模、三轮连续、全量双轮弄脏自证和 SE250 四轮多尺度压测均有留证。
- **构建已同源**：RTL、XSA、ELF、bitstream、BOOT.bin 通过 `SHA256SUMS` 约束；100 MHz 实现收敛。
- **算法边界**：当前系统不是任意 DNA 编码器；正式支持范围由 manifest、读长 profile、几何参数和阈值共同限定。

## 3. 尚未关闭的问题

### P1 · Stage1 吞吐

当前 Stage1 在读段维度并行、碱基维度仍部分串行，尚未证明 FPGA 在公平的优化 C 单核/多核基准上胜出。下一步按 `docs/11-optimization-plan.md` 的 T0→T2 执行。

### P2 · 多 payload 泛化

SE150/SE250 主要使用同一 R0.83 payload。需要新增 payload manifest、重新编码数据和独立最终哈希，不能把同一张图重复运行当作泛化证据。

### P3 · 错误鲁棒性曲线

需要对 substitution、insertion、deletion、覆盖度和阈值做可重复注入，报告成功率、原始误码、初始校验子和迭代次数。

### P4 · 上位机可维护性

Python 参考实现、C LDPC、协议会话、GUI 和结果验证仍需进一步模块化；上位机性能必须用 profiling 和逐位回归证明。

### P5 · 工程技术债

包括功耗实测、断连恢复、长期温度运行、许可证/权属确认、文档引用清理和新板迁移风险。没有实测的数据不得写成已完成指标。

## 4. 证据纪律

1. 构建、仿真、包装和历史 XSA 都不能代替板端 G3。
2. 最终图片哈希是端到端判据；中间级别必须同时记录适用范围。
3. 修改 RTL/固件后必须重新构建整套制品并刷新 `SHA256SUMS`。
4. 新运行必须生成新的带时间戳留证目录，不得把旧运行 ID 当成新版本证据。
5. 任何“更快/更省电/更通用”的结论必须给出同口径基线、输入哈希、重复次数和失败样本。
