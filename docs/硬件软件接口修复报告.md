# 硬件软件接口修复报告

## 概述
本报告详细说明了在DNA信息存储FPGA加速系统中发现并修复的关键硬件-软件寄存器映射冲突。

## 已修复的关键问题

### 1. ✅ 解码器（DECODER）寄存器映射不匹配（严重问题 - 已修复）

**问题描述：**
软件中的寄存器定义（`sw/app/echo.h`）与硬件实际寄存器映射（`hw/ip/desparsification_decoder_1_0/hdl/desparsification_decoder_v1_0_S00_AXI.v`）不匹配。

**旧的软件寄存器映射（错误）：**
```c
#define DECODER_REG_IN_ADDR         0x00U   // ❌ 错误
#define DECODER_REG_IN_BEATS        0x04U   // ❌ 硬件中不存在
#define DECODER_REG_OUT_ADDR        0x08U   // ❌ 错误
#define DECODER_REG_OUT_BEATS       0x0CU   // ❌ 硬件中不存在
#define DECODER_REG_START           0x10U   // ❌ 错误
#define DECODER_REG_STATUS          0x18U   // ❌ 错误
```

**实际硬件寄存器映射：**
```verilog
localparam ADDR_CTRL      = 6'h00;   // 控制/启动寄存器
localparam ADDR_STATUS    = 6'h04;   // 状态寄存器（IDLE, DONE）
localparam ADDR_IN_L      = 6'h10;   // 输入地址低32位
localparam ADDR_IN_H      = 6'h14;   // 输入地址高32位
localparam ADDR_OUT_L     = 6'h18;   // 输出地址低32位
localparam ADDR_OUT_H     = 6'h1C;   // 输出地址高32位
```

**新的软件寄存器映射（正确）：**
```c
#define DECODER_REG_CTRL            0x00U   // ✓ 控制/启动寄存器
#define DECODER_REG_STATUS          0x04U   // ✓ 状态寄存器（从0x18修正）
#define DECODER_REG_IN_ADDR_L       0x10U   // ✓ 输入地址低32位
#define DECODER_REG_IN_ADDR_H       0x14U   // ✓ 输入地址高32位
#define DECODER_REG_OUT_ADDR_L      0x18U   // ✓ 输出地址低32位
#define DECODER_REG_OUT_ADDR_H      0x1CU   // ✓ 输出地址高32位
```

**影响：**
- **STATUS寄存器不匹配**：软件读取地址0x18（实际是OUT_ADDR_L）而不是真正的STATUS寄存器0x04，导致无限等待循环和超时
- **IN_BEATS/OUT_BEATS寄存器不存在**：软件尝试配置不存在的寄存器，对硬件没有任何效果
- **仅使用32位地址**：软件只写入地址的低32位，高32位始终为0

**修改的文件：**
- `sw/app/echo.h` - 更新寄存器定义
- `sw/app/echo.c` - 更新解码器配置以正确写入64位地址，删除BEATS寄存器写入
- `sw/app/main.c` - 更新force_decoder_to_idle()函数

### 2. ✅ 64位地址处理（严重问题 - 已修复）

**问题描述：**
硬件期望64位DDR地址分成两个32位寄存器（HIGH/LOW），但软件只写入了低32位。

**旧代码（错误）：**
```c
write_reg32(DECODER_BASEADDR, DECODER_REG_IN_ADDR,  DEC_IN_ADDR);   // 仅低32位
write_reg32(DECODER_BASEADDR, DECODER_REG_OUT_ADDR, DEC_OUT_ADDR);  // 仅低32位
```

**新代码（正确）：**
```c
// 将64位地址分为HIGH/LOW写入
write_reg32(DECODER_BASEADDR, DECODER_REG_IN_ADDR_H,  (u32)(((u64)DEC_IN_ADDR) >> 32));
write_reg32(DECODER_BASEADDR, DECODER_REG_IN_ADDR_L,  (u32)(DEC_IN_ADDR & 0xFFFFFFFF));

write_reg32(DECODER_BASEADDR, DECODER_REG_OUT_ADDR_H, (u32)(((u64)DEC_OUT_ADDR) >> 32));
write_reg32(DECODER_BASEADDR, DECODER_REG_OUT_ADDR_L, (u32)(DEC_OUT_ADDR & 0xFFFFFFFF));
```

**影响：**
如果任何DDR地址的高32位非零，硬件将使用错误的地址，导致数据损坏或系统挂起。

### 3. ✅ 内存屏障（严重问题 - 已修复）

**问题描述：**
缓存刷新操作后没有添加适当的内存屏障就触发硬件，可能导致硬件读取陈旧数据。

**修复：**
在缓存刷新后添加显式内存屏障：
```c
Xil_DCacheFlushRange(DEC_OUT_ADDR, DEC_OUT_BEATS * 8);

/* 内存屏障确保缓存刷新完成 */
__asm__ volatile("dsb sy");
__asm__ volatile("isb");
```

### 4. ✅ 投票器（VOTER）寄存器映射（已验证 - 无问题）

**硬件寄存器映射：**
```verilog
0x00: CTRL_STATUS   // 控制/状态寄存器
0x04: IN_ADDR       // 输入DDR地址（32位）
0x08: IN_BEATS      // 输入拍数
0x0C: OUT_ADDR      // 输出DDR地址（32位）
0x10: OUT_BEATS     // 输出拍数
0x14: TOTAL_READS   // 要处理的总读取数
```

**软件寄存器映射：**
```c
#define VOTER_REG_CTRL_STATUS       0x00U  // ✓ 匹配
#define VOTER_REG_IN_ADDR           0x04U  // ✓ 匹配
#define VOTER_REG_IN_BEATS          0x08U  // ✓ 匹配
#define VOTER_REG_OUT_ADDR          0x0CU  // ✓ 匹配
#define VOTER_REG_OUT_BEATS         0x10U  // ✓ 匹配
#define VOTER_REG_TOTAL_READS       0x14U  // ✓ 匹配
```

**状态：** ✅ 无问题 - 软件和硬件完全匹配。

**注意：** VOTER使用32位地址（不像DECODER使用64位），这对于当前系统是正确的，因为所有地址都在32位范围内。

## 可能存在的其他问题

### VOTER IN_BEATS计算

软件当前计算：
```c
const u32 VOTER_IN_BEATS = TOTAL_READS * 6u;  // = 648000拍
```

这假设IN_BEATS表示"要读取的64位拍的总数"，其中每个读取由6个u64（48字节）组成。

**需要验证：** 检查硬件如何解释IN_BEATS：
- 选项A：64位拍的总数（当前软件假设）
- 选项B：读取数（硬件自动处理每个读取的6个u64）

如果选项B正确，软件应改为：
```c
const u32 VOTER_IN_BEATS = TOTAL_READS;  // 让硬件处理每个读取的6个u64
```

**需要检查的文件：**
- `hw/ip/differential_voter_1_0/hdl/differential_voter_v1_0.v` - 读取状态机
- 使用实际硬件测试以验证正确行为
