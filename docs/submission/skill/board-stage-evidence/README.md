# 技能包：端到端结果对了，不等于每一级都对——逐级取证与判据鉴别力

> 参赛提交物，不是本仓库的开发规范（见上级 README）。

## 适用场景

多级流水的加速系统（采集 → 预处理 → 计算 → 后处理），最终输出能和参考结果对上。
问题是：**这能证明什么？**

- 它能证明「这一次、这组参数下，整条链路是通的」；
- 它**不能**证明每一级都正确——上游的错误常常被下游吸收掉（投票、纠错码、滤波、量化）；
- 更危险的是：某些缺陷**注回去，最终结果仍然完全不变**。此时端到端判据对这个缺陷是瞎的。

## 使用方法

### 1. 每一级都留一份中间结果，并各自有参考

让每一级把输出写进可读位置（DDR 固定区间 / 文件），再用调试器或脚本导出，
与纯软件黄金模型逐级比对。典型判据表：

| 级 | 比什么 | 通过标准 |
| --- | --- | --- |
| 预处理/展开 | 逐字节 | 100% 相同 |
| 主计算 | 关键字段（分数、位置） | 分数 100% 相同；位置允许落在**并列最优集**内 |
| 中间聚合 | 逐位 | 差异数 ≤ 已知容差，且容差有出处 |
| 最终产物 | 哈希 | 逐位相同 |

**写判据时不要偷懒用「全绿」掩盖差异**：本项目写过「Stage1 4011/4096 逐位相同」，
读者只会觉得有 85 条错了；实际是分数 4096/4096 全同、85 条位置落在同分并列集内。
**差异要写清楚是什么、为什么允许**，否则答辩时会被追着问。

### 2. 给判据做故障注入，证明它会红

**没红过的判据不算判据。** 做法：把一个已知缺陷注回去，看判据是否变红。

如果注回去判据仍然全绿，说明这条判据对该缺陷**没有鉴别力**，必须另找判据。

### 3. 特别当心「结构性参数错了但结果不变」

常见于几何参数、步长、索引起点这类**只影响中间表示、不影响下游统计**的参数。
对这类参数要单独找一个**对它敏感**的判据（例如展开后的参考数据本身的哈希），
而不是靠最终结果。

### 4. 重复任务要能自证「状态真的被清干净」

连续跑两轮同样的任务、得到同样的结果，**不能**证明中间状态被复位了——
如果累加器只增不减、判决只看符号，残留值往往不会改变结论。
正确做法：**第一轮故意用不同的参数「弄脏」状态**，第二轮用判据参数跑；
两轮的原始回传若完全相同，反而说明判据没有鉴别力，应当判失败。

## 失效条件

- 逐级取证需要中间结果可读。若某一级只存在于片内 FIFO，就得先加一条导出通路（或计数器）。
- 导出动作本身不能干扰运行：**跑完再读，不要中途复位**，否则读到的是被清掉的中间态。
- 容差必须有出处（算法允许的并列、数值精度），不能为了让判据变绿而临时放宽。
- 故障注入要能安全回滚，建议用编译开关或独立分支，不要手改生产源码。

## 已验证效果

本项目的四级取证（每次板级验收自动执行）：

```text
展开参考数据   47,850 / 47,850  逐位相同
主计算         4,096 / 4,096    分数相同；4,011 位置相同，其余 85 条在同分并列集内
中间聚合       1,265 / 1,266    逐位相同（差异在容差内）
最终产物       图片 SHA-256 逐位相同
```

**鉴别力实测（这条最值钱）**：把「几何参数写死成另一种读长」的缺陷注回去，
15 个产物里有 14 个逐字节不变，最终图片哈希**照样正确**——
端到端判据对这个缺陷完全是瞎的。唯一会变红的是展开后参考数据的哈希。
于是这条被固化成哨兵判据。

**另一次**：曾用「两轮结果相同」证明累加器被复位，后来发现该判据恒绿——
因为累加器是带饱和的符号累加，残留值不改变符号判决。改成「第一轮用不同阈值弄脏」后，
两轮原始回传相差 24,839 / 64,800 bit，判据这才真正有了鉴别力。

## 来源

三件事：

1. 一次上板，最终图片正确，但后来发现某一级整体错位了一条记录——
   下游的多数投票把它吸收了，端到端判据没红；
2. 一次故障注入实验发现「改了几何参数，14/15 个产物一字不变」；
3. 一次把恒绿的判据当成了通过标准，写进了文档，几周后才被推翻。

共同点：**它们都不产生错误的最终答案，所以整套验证金字塔对它们失明。**
