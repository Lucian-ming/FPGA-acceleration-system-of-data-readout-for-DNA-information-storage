# 技能包：多个 AI agent 同时改一个仓库时，怎么不互相踩

> 参赛提交物，不是本仓库的开发规范（见上级 README）。
> 仓库内看板脚本的唯一权威源是 [`tools/agent_view.sh`](../../../../tools/agent_view.sh)（Bash，不含本题目内容）。本技能子目录没有携带脚本副本；将 `docs/submission/skill/` 单独复制出去时，须另行提供该脚本才能直接运行下面的命令。
> 2026-10-10去掉本目录逐字节重复副本；原附件在Git历史及本机备份保留，功能源码没有变化。

## 适用场景

用大模型协作开发时，很快会遇到两个问题：

1. **看不见**：同时开了几个会话/agent，人不知道每个在干什么、干到哪了、卡在哪；
2. **互相踩**：几个会话共用一棵工作树，Git 暂存区是**全局共享**的，提交内容会串。

这份技能包给的是两件经过实战的东西：一个状态看板脚本，和一条能挡住提交串扰的 Git 写法。

## 使用方法

### 1. 状态看板：每个 agent 都必须登记

```bash
# 开工前（拿到任务的第一件事）
tools/agent_view.sh start  --agent voter-opt --doing "在做什么" --why "为解决什么问题" --next "下一步"
# 换子任务 / 结论变化 / 启动长任务前
tools/agent_view.sh update --agent voter-opt --doing "..." --next "..."
# 受阻（把「在等什么」写进 --next）
tools/agent_view.sh block  --agent voter-opt --doing "..." --why "..." --next "等用户确认选哪块板"
# 交接前最后一件事
tools/agent_view.sh done   --agent voter-opt --doing "..." --next "..."
tools/agent_view.sh show                       # 看当前看板
```

脚本用 `flock` 串行化写入，支持并发；渲染出一份 `view.md`，人只看它就够了。设计要点：

- **三个字段都必须写具体内容**（带关键文件名 / 脚本名），写「处理任务中」等于没写；
- `done` 之后条目**自动从「当前状态」摘除**，完成记录留在「最近动态」里——
  看板上永远只剩还在跑的 agent，不会出现「早做完了还挂着」；
- 反过来，**超过 6 小时没更新的「进行中」会被自动标注「可能已中断」**，
  这是会话被杀或额度中断的典型残留，看到就接手或关掉；
- 看板是本机实时状态，**不进版本库**；结论和证据仍然要写进文档并提交。

### 2. Git：提交必须带路径

**这条是硬要求，不带路径迟早出事。** 原因：

> 暂存区（索引）是**整棵工作树共享的一份**，而 `git commit` 提交的是**索引的全部内容**，
> 不是「你刚才 add 的那些」。你 add 之后、commit 之前，别的会话 add 了东西，
> 或者跑了 `git pull --rebase`（autostash 会重置索引），索引就被改掉了。

正确写法：

```bash
git commit -m "..." -- path/one.c path/two.md    # 只提交这些路径
```

带路径的 commit **不看索引，直接取这些路径的工作树内容**，两个方向的串扰都堵住了。
实测（GNU git）：索引里有别人的文件、自己的文件完全没 add 时，
带路径 commit 仍然只产生 1 file changed 且内容是工作树里的新版；不带路径则是 2 files changed。

配套约定：

- 禁止 `git add -A` / `git add .`；
- 提交前 `git pull --rebase`，推完确认本地与远端 `0 ahead, 0 behind`；
- 并行时**指定唯一写入者**：子 agent 只交付文件，由主会话统一提交。

### 3. 派生子 agent 时要带上的三句话

给子 agent 的 prompt 里明确写：用哪个 `--agent` 名字（并行时不得重名）、
按 start/update/done 登记、不要自己动 Git。

## 失效条件

- 看板解决的是**可见性**，不是隔离。真正的资源冲突（同一个文件、同一块板卡、同一个串口）
  要靠任务划分或加锁，看板只能让人看见冲突。
- 带路径提交只保护**你点名的路径**；如果两个会话改同一个文件，仍然会互相覆盖。
- `agent_view.sh` 依赖 `flock`（util-linux），Windows 原生环境需在 WSL / Git Bash 下用。
- 看板不进版本库，所以**不能当交接文档**：结论必须落到 docs。

## 已验证效果

本项目并行开发期间的两次真实事故，都是「不带路径提交」造成的：

1. **别人的文件混进了你的提交**：一次纯 RTL 提交里混进了两份别人正在改的文档。
   当事会话确实只 add 了三个 RTL 文件，提交前也复核过状态；
2. **你自己的文件被踢出索引**：另一会话 add 完之后，暂存区里多出两个从没 add 过的文件，
   而自己的脚本反而掉了出去。元凶多半不是别人的 `add`，而是别人跑了 `git pull --rebase`。

**「add 之后再复核一次索引」堵不住**——复核与 commit 之间照样会被插入。
改成带路径提交后，再没发生过提交串扰。

看板方面：本项目连续多轮多会话开发，用户只看 `view.md` 就能掌握每个 agent 的状态；
「超时未更新自动标注」实测抓到过被额度中断的残留会话。

## 来源

两次提交事故 + 一次「有三个会话在跑，但没人知道哪个在跑什么」的混乱。
教训不是「要小心」，而是：**共享状态必须有机制约束，靠纪律约束不住**——
所以才把它做成脚本和一条能验证的命令写法。
