## 共同的提示词结构

这些提示词先描述角色要解决的项目问题，再划定可写路径、输入与外部依赖，最后给出验证出口和报告格式。它们反复要求：

- 从最新状态承接，不把历史快照当当前事实，不重复已有有效成果。
- 按证据区分 PASS、FAIL、未测和工具问题；记录实际命令、参数、来源与产物，不以“看起来合理”代替实测。
- 共享工作树中避免路径重叠；触板、综合和大型仿真先由 main 分配资源。
- 子 Agent 不执行 Git 写操作；交付前停止写入，由 main 审查并统一提交。
- 关键参数、数据几何、工具版本和证据边界写入阶段卡，避免子 Agent 依赖缺失的主会话上下文。

## 使用说明

本文是对项目内提示词来源的分类和摘要，不是逐字提示词转录。复核原始提示词时打开表中链接；复现某轮任务时还要从该任务原始记录取得对应阶段卡与 job_id，见 [agent-usage.md](agent-usage.md)。
