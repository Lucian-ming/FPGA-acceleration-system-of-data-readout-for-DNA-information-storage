## 1. 当前可以使用的基线（BKB220 / xc7z020 / PL 100 MHz）

### 1.1 资源与时序（整机 route，实测）

| 配置 | LUT | RAMB36 | DSP | WNS / WHS | 失败端点 | DRC |
|---|---:|---:|---:|---:|---:|---:|
| P4（4/0） | 15,447 (29.0%) | — | 3 | +0.680 / +0.036 | 0 | 0 |
| P16（16/1，K=1） | 33,987 (63.9%) | 44 | 3 | +0.617 / +0.017 | 0 | 0 |
| **P16（16/1，K=2 冻结版）** | **35,702 (67.1%)** | 48 | 5 | **+0.313 / +0.036** | **0**（共 88,748） | **0 Error** |

K=2 那一行是 2026-10-14 写死后重建的整机 route；**它与写死前那一版逐项相同**
（35,702 / 48 / 5 / +0.313），说明把可配置 `parameter` 改成 `localparam` 没有改变任何行为。
K=4 曾实测 63,246 LUT（合计）/ 54,164（组合）**超过 XC7Z020 的 53,200**，`place_design` 硬失败——
**K 是被器件容量定死的，不是价值判断**。

出处 [P4/P16 构建摘要](benchmarks/bkb220-p4-p16-100mhz-build.md)。**不得把 OOC 能放下当成整机通过。**

### 1.2 端到端（全量 103,616 条板端记录）

| 分段 | 参考包 | 上传转正后 | **K=2 写死后** |
|---|---:|---:|---:|
| 读段上传 | 4.27 s | **0.40 s** | 0.40 s（未变） |
| 板端「下发→收齐载荷」段 | 9.33 s | 9.33 s（未变） | **6.06 s** |
| 上位机 LDPC | 0.653 s | 0.653 s | 0.653 s |
| **整轮** | ≈ 14.25 s | **≈ 10.4 s** | **≈ 7.1 s**（推算，见下） |

**K=2 那一列来自同小时背靠背 A/B**（2026-10-14，两次 run 相隔 3 分 20 秒，均 G3 PASS、
判据同为 `fcd0cf90…b1f2c3`、均 103,616 条记录 / `score_min=67`）：
K=1 参照包 **9.08 s** → K=2 冻结版 **6.06 s**，**快 1.50×、省 3.02 s**。
判据与方法见[多碱基探针报告](benchmarks/stage1-multibase-ooc-probe.md)。

⚠️ **口径**：该段是板端「下发任务→收齐载荷」，**不含**读段上传与上位机 LDPC；
且**每个配置各只测了一次**，不是 ≥3 次的统计。**「整轮 ≈7.1 s」是按「上传+该段+LDPC」简单相加的推算**，
不是同口径的整轮实测，引用须标明。

⚠️ **`t_result` 同一天内会漂移**（今晨 8.68 / 上午 8.95 / 傍晚 9.34 s，约 ±7.5%）。
**任何 A/B 必须同小时重测参考包**，否则会把结论做反。见
[上传段 benchmark](benchmarks/bkb220-p16-speed-a-upload.md) §5。

## 2. 已经关掉的方向（**不要再当优先级**）

每一条都有实测或结构证据，细节见各自出处。

### 2.1 实测证伪

| 方向 | 为什么关掉 |
|---|---|
| **删 `PIPE_RUN_SLEEP_US` 节流** | 三档 200/50/0 斜率 0.079086/0.078348/0.079057 ms/记录，**差异 <1%**，端到端没快 |
| **"lwIP poll 空等 2,777 ms"** | 测于 2026-09-11、**早于 P12-B 事件驱动改造**，不代表当前固件 |
| **逐 BD cache flush / BD 提交回收** | 函数级实测合计 **102 ms（1.1%）**，不值得动 |
| **lwIP 收包路径** | **7.7 ms（0.08%）**，可忽略 |
| **Stage1 算法提前终止** | 真实 SE150 数据 261 万样本：**40,800 个块全部要满 150 拍，提前退出 0 次**。前两名分差中位仅 2 分、**14.69% 完全并列**，且块内 64 条记录锁步 |
| **减少 DDR 搬运** | 可证明省时 **0 s**；PS 侧全部可归因工作才 194 ms，清零也只是这个数 |
| **流式（边收边算）** | 上传已从 3.9 s 压到 **0.40 s**，重叠上限就是它。协议改动风险不变、收益缩水一个数量级 |
| **LDPC 搬到 PL** | **性能上关掉**：单路 0.381 s，比 PC 上已有的 C 实现（0.182 s）**还慢**；须 ≥2~4 路才占优，且上位机一旦与下一轮重叠，稳态 **省 0**。**但资源上未关闭**——见 §3 第 4 项：用户 2026-10-14 已按**展示/集成**定位立项 |
| **TX_STREAM 压缩** | 归档已尝试四次并放弃；真正约束是 PL 处理每帧的墙钟时间，原设计是**时间节拍器**不是容量节流器 |

### 2.2 资源证伪

| 方向 | 为什么关掉 |
|---|---|
| **加 `P_WAYS` 到 32/64** | 外推整机 58.7k / 108k LUT，**均超 XC7Z020 的 53,200** |
| **8-way / 128×4 展开** | LUT 外推约 125% |
| **精确种子索引** | 读段与水印最佳位置最长连续精确匹配仅 5~7 nt，16-mer 命中概率 ≈1.5e-05 |

### 2.3 保留但**不优先**

Voter/Decoder 微架构：板上周期实测 Stage2 644.9 ms、Stage3 0.022 ms，
**即使两级全归零，端到端提速 <1%**。未经新测量不要重做。

## 3. 当前优化顺序（2026-10-13）

**剩余价值几乎全在 PL。** 板端 9.33 s 里 PL 约占 87.8%（约 8.2 s），PS 全部可归因工作只占 2.1%。

| # | 项 | 预期 | 状态 |
|---|---|---|---|
| 1 | **Stage1 每拍 K 个碱基** | K=2 → 约 6.0 s/轮 | ✅ **完成并转正**：K=2 写死、G3 PASS、**同小时 A/B 1.50×**（9.08→6.06 s）。K=4 因容量硬失败已关闭 |
| 2 | **块级开销重叠** | 固定开销占块长比例未在本轮重测 | 未做（K=4 前提已消失，需按 K=2 重新评估） |
| 3 | **LDPC 与下一轮重叠** | 0.653 s/轮界，**零 FPGA 资源** | 未做 |
| 4 | **片上 LDPC**（用户 2026-10-14 立项） | 展示/集成项，**性能收益 ≈0** | 见下；最大未知是 bank 地址转换 |

**天花板**：PS ≈1.1 s（动不了）+ PL 最好约 2.3 s + 上传 0.2 s → **整轮地板约 3.6~4.0 s**（现 10.4 s）。
再往下只有两条路，且都要用户拍板：**加 `P_WAYS`**（资源已封死）或**改算法少搜位置**（改变结果）。

### 测量纪律（本轮新增，必须沿用）

1. **同小时重测参考包**——`t_result` 一天漂 ±7.5%，跨小时比会把结论做反；
2. **`t_result` 口径与端到端口径分开说，不混**；
3. **先写能变红的判据再动手**；失败证据保留，不得为全绿放宽门禁。

## 4. 项目定位与后续边界

可以说明复杂读出系统在 PS/PL/PC 之间闭环、真实接口与可鉴别判据、指定数据/profile 下的正确性，
以及**带完整口径**的实测收益。以下均需独立证据、不得宣称：
任意 payload / 任意错误率、工业级稳定、百倍通用加速、低功耗优势（**无功率计，未测**）。

泛化与 sub/ins/del、覆盖度与阈值按 06 复核；**FAR 是累加器污染度，不是失败率**。
算法重写、SE250 迁移、软信息 LDPC 保留在后续任务池，不扩张本轮 SE150/P16 范围。
