## 本次复跑

在仓库根目录执行，全部退出成功：

```bash
python3 tools/golden_model.py verify-code
bash tools/run_sim.sh datapath
bash tools/run_sim.sh axi
bash tools/run_sim.sh stage1
bash tools/run_sim.sh host
bash tools/run_sim.sh syntax
```

关键结果：

- Stage3 数据通路：随机背压下 1,013 拍、64,800 bit 与黄金码字逐位相同。
- Stage3 AXI：严格从机（零延迟 B、受限地址队列）写出 1,013/1,013 拍且逐位相同。
- Stage1：运行约 618 万周期，64/64 分数和码字一致；2 条 59 分读段为允许的并列峰。
- 水印展开：50×957 = 47,850 个符号全部与黄金向量一致。
- 语法检查：DNA 核、Voter、Desparsifier、死文件 `five_to_four_decoder.v` 均能由 Icarus 解析。

以上均为离线证据。`bash tools/run_sim.sh syntax` 只是语法检查，不能代替综合、时序或功能验证。

## 尚未闭合的阻塞项

1. **Stage2 是当前第一优先级。** 没有 Voter 的黄金 RTL Testbench，也没有其输出与
   `tests/golden/stage2_expect.hex` 的逐位比对。
2. **D1 未完成。** 发送正向和反向互补两份读段后，Voter 仍会等权处理两份；需要实现并验证按
   `score` 配对择优或加权，不能把主机“双份发送”当成方向识别。
3. **C1/C2 未完成。** `echo.c` 的 Stage2 配置与 cache 范围仍使用固定
   `TOTAL_READS=108000`；非 64 倍数尾批也没有可靠语义。
4. **B1/B3 仅完成软件或离线一侧。** 需要把真实 Stage2 输出 XOR 后与
   `stage2_expect.hex` 比较，并验证 DNA 顶层接收的每一区域水印。
5. **没有板端端到端验收。** 唯一的完成判据仍是实际 FPGA 回传经 LDPC 后与 R0.83
   `source_bit.txt` / `Milk coronet.jpg` 分别逐位/逐哈希相同，且生产路径不得读取参考答案。
6. **工程重建和换板未开始。** `top.xdc` 仍为 0 字节，Tcl 仍不能单独再生历史 PS7/DDR/MIO/PHY 配置。

## 推荐下一步

先为 `differential_voter_v1_0.v` 建立文件型 AXI/DDR Testbench：以当前 Stage1 黄金输出作为输入，
以 `tests/golden/stage2_expect.hex` 为唯一判据，并覆盖随机 AXI 背压、实际读段数与 64 倍数边界。
该测试通过后，再验证 B3 的 XOR 和 D1 的方向取舍；不要先做 LDPC 上板、任务参数化或换板。
